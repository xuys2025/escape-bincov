2026-10-09（UTC+8）。分支 `fix/shop-drag`，从最新 main `43a342c` 建立，独立于 PR #22。缺陷登记见本地工作标准 `缺陷登记/商店拖动-20261008`（含用户两次反馈与截图）。

**结果：** 修理铺、卫生所购物车的鼠标拖放恢复可用，覆盖以下操作：
- 买入：商人物品 → 待买；

## 二、原因

`030fa74`（2026-10-05，随 PR #10 合入 main）把背包拖动改成了指针事件实现，但商店仍走浏览器原生拖放。同一次提交加的三处保护，各自都会让原生拖放失效：

1. `src/style.css` 的 `.item, .item img { -webkit-user-drag: none; }`：Chromium 不开始原生拖动，根本没有 dragstart。
2. 全局 `pointercancel` 监听：原生拖动一开始，浏览器就会发出 pointercancel，拖动状态被清空。
3. 全局 `pointerout`（relatedTarget 为空）监听：同样在原生拖动开始时清空拖动状态。

drop 到达时拖动状态已经为空，`commitDrop` 静默返回，所以玩家看到的就是「拖了没反应」。原有回归只用点选放置买卖，没有拖放用例。

## 三、修复（只改 `src/ui.ts`）

- **商店改走背包已有的指针拖动：** 去掉 `onpointerdown` 里对商店的提前返回。拖动预览、虚影、Esc 取消、失焦/隐藏/指针取消时的清理，都和整备页背包一致。
- **删掉不会再用的原生拖放路径：** 物品一律 `draggable="false"`，删除 `ondragstart/ondragend/ondragover/ondragleave/ondrop`。`commitDrop` 改为直接接收这次拖动和落点，不再借 DataTransfer 传 JSON。
- **R 键在商店拖动中不旋转：** 购物车不保存旋转，物品保持原方向；背包和搜刮里 R 照常旋转。
- **不再静默失败：**
  - 落在格子上但拖动已失效时，提示「拖放未完成，物品仍在原处。」；
  - 规则不允许的放置照常提示原因，例如「先放入待买或待卖区，再统一结算。」；
  - 把商人物品拖回商人物品区视为改主意，不提示；
  - 落在格子以外，物品留在原处，不提示。
- **触屏不变：** 仍用「选中 → 移动格位 → 点格」，与背包一致。
- **CSS 不变：** `-webkit-user-drag: none` 保留，防止浏览器把物品图片当原生拖动。

购物车在结算前只是内存里的清单，`Shop.moveShopItem` 只改清单；结算仍走原来的 `Shop.settleCart` 加 `saveSession.mutate` 原子事务。修复没有动 `src/shop.ts`、存档、价格或规则。

## 七、交给 Astra：交易/存档层面的观察

本次没有发现需要改规则或存档的缺陷：写入失败时现金、仓库和已存档字节都不变，重试只扣一次。下面几点属于规则侧的取舍，前端不宜自行决定：

1. **结算拒绝原因不分类。** `Shop.settleCart` 只返回 true/false。以下情况前端都只能显示同一句「交易未完成，请检查现金、仓库空间和清单」：
   - 仓库在别处被改过（与清单创建时不同）；
   - 现金不够；
   - 仓库放不下；
   - 清单里有不合规物品。

   如果希望提示具体原因，需要 `settleCart` 返回拒绝原因。
2. **待买区的位置不影响结算。** 买入的物品结算时由 `D.addItem` 自动放进仓库，玩家在待买区摆的位置不会保留；而在商店里对仓库物品的挪动，会照清单生效。这是不是想要的规则，请确认。
3. **清单失效后的处理。** 如果仓库在其他窗口被改，本窗口的清单会一直被拒绝，玩家只能离开商店重开清单。是否需要自动刷新或给出专门的提示，由规则侧决定。
