## 首轮失败及处置

1. `pnpm test:station` 第一次 31/44。主要原因是挂院子时先渲染了一次旧页签界面到隐藏的 `#ui`，页面上出现两套同名网格，拖放和定位都找错元素。改为挂院子前就设置 `app.station`，旧界面直接清空。
2. 同一轮：Phaser 循环状态字段写错（应为 `loop.running`）；“罐头回仓库”“绷带进安全箱”断言按物品编号判断，但合并堆叠会换编号，改为按数量判断；训练 120 秒步骤一半时间走出了训练区，改为在区内来回走。均为测试问题。
3. 同一轮：1280×720 下升级后的仓库 + 老栓说话行让修理铺面板多出 40 像素（真实问题），改为桌面面板按实际高度缩小格子。
4. 同一轮：20 次重挂后 GPU 纹理 339 → 370（真实问题）。地面贴图没有登记释放，补上后 347 → 347；另外两次采样改为相同的等待时间，避免把人物动作帧的延迟创建算成泄漏。
5. 单测第一次 271/273：`save-flow` 在 Node 里导入界面模块时读了 `location`。改为没有 `location` 时按默认处理。
6. 回归第一轮 24/25：`test:title` 普通入口预期“进入”后直接是旧页签，并比较存档原始字节。现在普通入口是院子，改为经过院子的“页签”按钮，并比较存档里的进度（当时只对照 profile；检查点还会推进受规则约束的休息计时，不能笼统视为只有版本号和时间变化）。其余 24 套第一轮即通过。
7. 第一轮回归的测试脚本是由 PATH 上的 Node 22.22.2 执行的（pnpm 本身在 Node 24 上）。仓库要求 Node 24，此后把 Node 24.19.0 放到 PATH 最前全部重跑。
8. 第二轮（Node 24）25/27：
   - 新增的 A4 本想验证“没有 WebGL 时退回页签”，结果发现 Pixi 8.22 在没有 WebGL 时会自动改用 Canvas 2D 渲染，院子照样打开，但 Canvas 渲染不支持发光层的叠加混合，人物全成了黑色剪影（运行时看过失败截图，清理结果目录时删掉了，没有保留）。这是真实问题：现在院子只接受 WebGL 渲染器，其他情况走页签回退并提示。
   - `test:title` 在窄屏手机尺寸下，院子的“页签”按钮收在“功能”菜单里，测试助手没有先打开菜单。玩家路径没问题，改了助手。
   以上改动后重新打包，第三轮全部重跑。
9. 第三轮：station 46/47，A4 的回退本身成功，但院子把这次启动失败用 `console.error` 记了一行，套件把它算作页面错误。这行日志是应当的（确实是画面启动失败），改为 A4 只认这一条预期日志，没有改构建；在同一份构建上重跑 station 47/47。其余 25 项第三轮全部通过，上表即这份最终构建的结果。
