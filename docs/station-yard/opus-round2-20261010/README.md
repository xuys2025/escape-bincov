## OPUS-STATION-INPUT-01：“功能”菜单被“交互”按钮挡住，点击误开出击

**原因。** 手机上“交互”是一个 72 px 的圆形按钮，固定在右下（距右 18、距底 70），层级高于快捷栏。竖屏窄屏把快捷栏收成“功能”按钮，展开后十个按钮排成一竖列从右下往上长，正好穿过“交互”按钮：整备、修理铺的中心点落在“交互”上，站在院门前时它对准“出击准备”，于是点整备打开了出击。同一个按钮在全屏面板（整备、修理铺）打开时也一直浮在面板右下，压住下面的格子。另外，菜单开着时点画面会让人走过去，横竖屏切换后菜单保持展开，位置还是旧屏幕的。

**改法。**
- “交互”按钮只在能自由走动时出现：菜单展开、任意面板/弹窗/对话框、出门/回站/通电动画期间都不显示。
- 窄屏（宽 ≤ 640）的菜单改成两列卡片（高度 ≤ 480 时三列），按“整备 修理铺 / 卫生所 任务 / 设施 身体 / 出击 页签 / 菜单”的阅读顺序排列，“功能”键在最下面横跨两列用来收起；菜单层级最高。
- 菜单开着时点画面只收起菜单、人不走；Esc 收起；进入任一面板时收起；窗口宽度变化（旋转）时收起，只改高度（手机地址栏）时保持。
- 触屏时底部提示条居中在“交互”按钮左侧的区域里，不再盖到按钮上。

**验证（真实触摸 / 鼠标输入，不用 force，也不靠测试接口开面板）。** Sol 的 H17 断言原样保留；新增 I1–I5 共 14 项：每个可见快捷按钮的中心和四个内侧点用 `elementFromPoint` 判定命中自己，“交互”与任何快捷按钮矩形不相交，再用手指点开整备/修理铺并核对实际打开的面板。

## OPUS-STATION-LIGHT-01：通电后墙面和屋顶逐格突变的明暗块

**原因。** 地面用的是平滑（抖动量化）的光照图，但每块墙砖是一个精灵，整块只在脚下取一次光照、染一个颜色。相邻两块的取样点相隔 32 像素；窗户和门口外的地面溢光半径只有 46–62 像素，往往只照到一两块，于是墙顶一圈、墙面和竖向墙柱一块亮一块暗。墙顶的取光还按砖块归属的房间决定，房间墙与院墙相接处也会跳。屋顶本身每块是一个整体、一个亮度，没有格子；Sol 截图里“屋顶”上的格块是屋顶边缘那一圈墙顶。

**改法（光照方案自定，固定雨夜和两种供电都不变）。**
- 每块墙拆成同一贴图的若干光照小格：墙顶 4×4 格（8 像素）铺在它的地面方格上，墙面 8 列（4 像素）沿墙脚。光照在砖块的四角和边中点取样，这些点与相邻砖块共用，再在小格之间插值，所以亮度每 8/4 像素渐变，接缝处不再突变；竖向墙柱上下相邻的墙顶同样连续。
- 墙顶的取光只看角点位置：露天光加上该点所在房间（含墙）的一半室内光，不再看砖块归属哪栋房子，房间墙与院墙相接处也连续。
- 墙面相邻两块分别从室内、室外取光时（例如门洞边），共用边取两侧的平均值，两块看到的是同一个值。
- 窗户和门口外的地面溢光标记为 `ground`：照亮地面和站在那里的人，不再照到开口周围的墙面（发光的窗户本身不变）。
- 画面外的墙不取光也不绘制，回到画面的那一帧重新取光；墙格纹理在卸载院子时随视图释放。

**验证。** 新增 L1，在实际渲染的帧上测（不是读代码里的颜色）：对视野里每一处“同一墙面”的相邻砖块接缝（行内墙面接墙面、墙顶接墙顶，竖向墙柱上下墙顶），取接缝两侧 4 像素带内“渲染亮度 / 贴图亮度”的中位数，求两侧的差。门、窗、院门、被屋顶或棚顶盖住的像素、半透明（玩家在后面）的墙不计。墙角处“室内墙面”接“侧墙墙顶”是两种表面的分界，不算接缝。门槛：p90 ≤ 0.05，最大 ≤ 0.10。
