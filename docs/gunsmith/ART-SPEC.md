- 没有 Sol 图时用 `src/coast-view/art/actors.ts` 的 `paintWeapon()` 程序画，手套色画在枪上。#39 的样本 M4A1 在 `runtime.ts` 的 `weaponLook` 里映射成 `rifle`，玩家没有对应的 Sol 图，所以手里是程序画的 31×10 步枪。

  - `heldLength()` 按 1 − 0.5·|sin(角度)| 缩短朝南北的枪；朝西用 `scale.y = −1` 镜像。
  - `syncArms()` 让扳机手臂伸到支点，前手臂伸到沿枪管 `support` 像素处；单手武器的前臂垂下。
- 子弹从身体中心出生，射程补 17 像素（`runtime.ts` 的 `MUZZLE`，#39 决定）。画出来的枪口只管火光和曳光，不管判定。

### H 持枪

- 只画朝东：枪口向右，上面朝上。朝西、朝南北的样子由运行时镜像和缩短，不另画。
- 枪身长度参照已验收图：手枪 15–18，冲锋枪 22–27，霰弹枪 30–34，步枪 28–34（AUG 无托约 26），精确步枪、栓动步枪、轻机枪 34–38。原厂配置高 ≤ 11（含手套）。
- 颜色沿用持枪图已有的色（`#242321`、`#393733`、`#4b4842`、`#625b4f`、`#777268`、`#a49b88`、`#75634e`、`#784d3d`、`#a27351`、`#59604a`、`#8a7a61`、`#ab9370`、`#b6a080`）和 [2.5D 设计](../COAST-2_5D-ART-DESIGN.md) §3.2 的色板。单个零件 ≤ 8 色，组合后 ≤ 16 色。外沿在需要和地面分开的地方用 `#242321` 收边，不要求整圈。
- 玩家手套色 `#4a463c`（`textures.ts`）。手套单独画成小图，组合时最后盖上；零件图上不画手（第 3.4 节）。
- 透视描边 `|rim` 由运行时生成，不用画。

### I 格子图与 Q 方图

- 画法、颜色、墨线照现有程序图标（`items.ts`、`inventory.ts`）：材质用 `C` 的钢、木、黄铜等色阶，外轮廓 1 像素墨线，不画手。单个零件 ≤ 8 色，组合后 ≤ 16 色。
- 显示一律整数倍。院子详情的 `.dico`（`station.css` 里高 44 或 28 像素）和面板小图（`panels.ts` 的 `icon()`）现在用 CSS 固定高度，不是整数倍，M2-08 接入时一起改。
- 组合宽不超过“占格列数 × 36”，高不超过“占格行数 × 26”。这样在 80 像素格里能放 2 倍，在 54 像素格里放 1 倍。超出时由 M0-05 的占格规则把成枪加宽或加高，不压缩比例。
- 行数由弹匣定（M3-12，维护者 2026-10-29，[CONTRACTS 的表](CONTRACTS.md#m3-12-决定2026-10-29)）：箱式弹匣 2 行，长弹匣或弹鼓 3 行，管状弹仓、顶置弹匣和握把里的弹匣 1 行。所以弹匣按真枪的长短画，2 行最高 52、3 行最高 78，不要压扁。
- Q 方图：新枪各画 24、32 两张，像现有三把枪那样是局部特写，不随配置变。配件只画 24 像素一张，32 像素场合居中放（RPG 物品的先例，`paintRpgItem` 偏移 4 像素），格子图用默认的 24×24（第 5 节）。
- 地上的枪和 HUD 武器卡原定用方图（第 9 节第 3 条）。维护者 2026-10-27 看过 M2 后改为用 H 原厂配置去掉手套的侧面图（方图是局部特写，在地上认不出），仍看不出配置；方图留给列表和详情。

### W 工作台

- 按 I 的轮廓和比例在 2 倍分辨率上重画，多画螺丝、导轨齿、纹理等细节。不能把 I 最近邻放大充数（PLAN 第 12 节：不以同一张图简单放大代替全部场景）。
- 界面按放得下的最大整数倍显示（桌面一般 3–4 倍，手机 2–3 倍），`image-rendering: pixelated`。插槽按钮放在各挂点上（W 坐标乘倍数）。空插槽的标记由界面画，图上不画。
- 单个零件 ≤ 12 色，组合后 ≤ 24 色。

## 3 锚点

### 3.1 坐标约定

- 每张图左上角像素是 (0, 0)，向右、向下为正，坐标都是整数像素。
- 子件的 `anchor` 像素压在父件的挂点像素上，重叠 1 像素，接缝处只留一条墨线。
- 锚点和挂点都在自己的画布内。手套小图的锚点可以落在透明像素上。
- 三种输出各自给坐标，不互相换算。自查时 W 的挂点约等于 I 的 2 倍，误差不超过 2 像素。

### 3.2 每把枪（H 机匣图上）

| 字段 | 含义 | 已验收旧枪 | 样板两枪 |
| --- | --- | --- | --- |
| `grip` | 旋转支点，也是扳机手臂的终点 | 卡宾 [8,4]，手枪 [6,6]，霰弹 [11,6] | 放在后手手套上沿附近 |
| `bore` | 枪管中心：第 r 行 1 像素粗写 r+0.5，占 r、r+1 两行写 r+1 | 卡宾 3.5，手枪 2.5，霰弹 2.5（沿用像素算法的值，位置不变） | Sol 定，写进清单 |
| `tip` | 原厂枪口：最外一列的右沿 x，y 同 `bore` | 卡宾 31，手枪 17，霰弹 32 | Sol 定 |
| `forward` | 支点沿瞄准方向离胸口的距离 | 手枪 8，长枪 0 | G17 8，M4A1 0（运行时常数，可调） |
| `hand` | 前手位置，`support` = 前手 x − 支点 x | 卡宾 support 12，霰弹 10，手枪 0 | M4A1 由原厂护木给；手枪前手就在支点上，support 0 |
| `oneHanded` | 单手 | 只有匕首和棍 | 二十把枪都不是 |

组合后的 `bore` 永远取机匣的值。装枪口件、换枪管都不改枪管行，瞄准线不会跳。

### 3.3 挂点（三种输出都给）

| 挂点 id | 插槽 | 配件 | 谁提供 | 零件的 `anchor` 放在 |
| --- | --- | --- | --- | --- |
| `top` | 顶部导轨 | O03–O12 | 机匣原生（见 WEAPONS 改装入口），或基座 | 瞄具最下一行的中间像素 |
| `micro` | 微型瞄具位 | O01、O02 | G17 原生，或 A01–A03 | 同上 |
| `mount` | 基座位 | A01–A08 | 机匣 | 基座最下一行的中间像素；基座再给 `top` 或 `micro` |
| `muzzle` | 枪口 | M01–M12 | 原厂枪管或枪管模块；没有单独原厂枪管图的枪（G17、旧三枪）由机匣给 | 枪口件最左一列、枪管上沿那一行 |
| `barrel` | 枪管模块，替换原厂枪管 | B01–B10 | 机匣 | 枪管最左一列、上沿那一行；枪管再给 `muzzle`（最右一列、上沿那一行）和 `tip` |
| `handguard` | 护木，替换原厂护木 | H01–H10 | 机匣 | 护木最左一列里紧贴枪管下沿的像素；护木再给 `under`、`side1`、`side2`、`hand` |
| `stock` | 枪托，替换原厂枪托 | S01–S10 | 机匣 | 枪托最右一列里和机匣对接的像素，同一把枪的枪托用同一行 |
| `rearGrip` | 后握把，替换原厂握把或握片 | P01–P08 | 机匣 | 握把顶行最左的像素 |
| `under` | 下导轨 | F01–F07 | 护木，或机匣原生（UMP45、Vector、AUG） | 握把顶行的中间像素；握把再给 `hand` |
| `bipod` | 支撑脚架位 | F08 | SVD、M14、M700、RPK 的机匣 | 脚架顶行最左的像素；首版只画收起 |
| `side1`、`side2` | 侧导轨 | T01–T03、T05–T07、T09、T10 | 护木，或机匣原生（UMP45、P90、Vector、AUG） | 设备夹在导轨上那一行的中间像素；设备再给 `beam` |
| `pistolSide` | 手枪侧挂位 | T04、T08 | G17、M1911、P226 的机匣 | 同上 |

“中间像素”在偶数宽时取左边那个。父件的挂点按同样的规则选在父件上：例如 `muzzle` 挂点是枪管最右一列、上沿那一行，枪口件的锚点压在它上面，两件重叠一列。

其他字段：`tip`（枪管、枪口件的新枪口）、`hand`（护木、前握把、手枪机匣的前手位置）、`beam`（激光、灯的出光点，运行时从这里画光束，M2-03）、`layer`（不按默认层序时才写）。配件在某种输出里没有图时（例如 H 里的后握把），组合沿用原厂件。

### 3.4 枪口怎么跟着变，手套和层序

**枪口链**

1. 机匣 → 原厂枪管（或换上的枪管模块）给出 `muzzle` 挂点和 `tip`。
2. 装了枪口件：它的 `anchor` 对上 `muzzle`，组合的 `tip` 改用枪口件的 `tip`。
3. 短枪管模块（B03、B05、B07、B10）让枪口后退；长枪管和带螺纹的枪管（B01、B02、B04、B06、B08、B09）让枪口前移。消音器 M03、M04、M07、M08、M12 在 H 里把枪口推出 4–10 像素（短的 M03 约 5，步枪和精确枪的更长）。
4. 运行时用组合的 `tip` 放火光、曳光和烟，替换 `barrelTip()` 扫像素；`art.muzzle` 跟着变长；`bore` 不变。
5. 子弹仍从身体中心出生、射程补 17 像素（#39），和画出来的枪口长短无关。贴墙时长枪口画进墙里只是画面，不改判定。
6. H 里侧挂设备、收起的脚架、前握把不能伸出 `tip` 那一列，像素扫描的旧路径才不会认错枪口。

**手套（只在 H）**

- 三张小图：`glove-rear` 盖在 `grip` 上；`glove-front` 盖在护木（或机匣）的 `hand` 上；`glove-foregrip` 盖在前握把的 `hand` 上。前手按“前握把 > 护木 > 机匣”取最外一层。
- 手枪只盖后手；两只手臂都伸到支点，一团手套盖住。
- 旧枪的已验收图手套是画死的。卡宾的前手留在原厂护木那一层；换上 H05 后，前手改用 `glove-front` 盖在 H05 的 `hand` 上。
- 只画玩家的手套。缓存键仍带 kind，以后敌人拿改装枪时按 kind 换手套色。

**默认层序（从后往前）**

枪托 → 后握把 → 弹匣 → 枪管 → 机匣 → 护木 → 前握把、脚架 → 基座 → 瞄具 → 枪口件 → 侧挂设备 → 手套（H）。手枪的加长弹匣（G01、G02）画在机匣上面，因为原厂弹匣藏在握把里；AUG（弹匣在握把后）、P90（弹匣在机匣顶上）按需写 `layer`。

## 4 组合（M2-10 的实现契约）

### 4.1 输入和步骤

输入：枪型 id、配置签名、素材版本、输出（H、I、W），H 另加持枪者 kind。Runtime 给玩家发布只读的外观 `{ gun, sig }`，不发布像素和 UID；敌人照旧用 `WeaponLook`。

1. 取这把枪在这种输出下的机匣图。
2. 替换类插槽（`barrel`、`handguard`、`stock`、`rearGrip`、`mag`，以及原厂带照门的 `top`）有配件用配件，没有就用原厂件，原厂没有就空着。
3. 加装类插槽（`top`、`micro`、`mount`、`muzzle`、`under`、`bipod`、`side1`、`side2`、`pistolSide`）有配件才画。子件挂在父件给的挂点上，最多三层（PLAN 第 5 节）。
4. 位置 = 父件挂点 − 子件锚点，整数像素。算出所有图的外框，平移到 (0, 0)，得到画布大小、支点、`bore`、`tip`、`hand`、`beam`，以及 W 上各插槽（含空插槽）的位置。
5. 按层序用 Canvas 2D 画：`imageSmoothingEnabled = false`，只平移，不缩放、不旋转。H 最后盖手套。
6. H 交给 `Textures` 的新组合入口，返回和 `weapon()` 一样的字段再加 `tip`、`bore`，并生成 `|rim`；I 转成 data URL；W 保留 canvas。

### 4.2 缓存键

`gs:<输出>:<枪型>:<配置签名>:r<素材版本>[:<kind>]`

- 配置签名：装上的配件按挂点路径排序拼起来，例如 `handguard=H01,handguard/side1=T01,handguard/under=F01,muzzle=M06,top=O03`。原厂件不写，空签名就是原厂配置。
- 不含实例 UID：配置相同的两把枪共用一张图；同型号不同配置一定是不同的键，不会串图（PLAN 第 12 节）。
- 不含设备开关：激光和灯的光由运行时画，不进贴图。
- 素材版本取改枪素材清单的 `revision`，换素材后旧键自然作废。kind 只有 H 需要（手套色）。
- 视图里按 `${weapon}:${kind}` 缓存的 `barrelTips` 改用组合键。组合图自带 `tip`、`bore`，不再扫像素。

### 4.3 上限和生命周期

| 缓存 | 上限 | 放在哪 | 什么时候释放 |
| --- | --- | --- | --- |
| H 组合 | 每个行动视图 8 张（各带一张 rim），最久没用的先淘汰 | 视图图集的独立纹理 `atlas.add(key, canvas, true)`，能单独 `drop` | 淘汰时 `drop`，再用 `releaseManagedSlots` 清掉 Pixi 的空槽（`renderer-lifetime.ts`）；换楼层保留；视图销毁时随 `Textures.destroy()` 全部释放 |
| I 组合 | 每页 64 个 data URL，最久没用的先淘汰 | 单独的小缓存，不放进无上限的 `painted()` | 淘汰即丢 |
| W 组合 | 4 张 canvas：当前、候选、两个预设预览 | 工作台 | 关工作台时全部丢掉 |
| Q 方图 | 每种物品固定两张 | 沿用 `painted()` | 不释放 |
| 零件解码 | 出击时解码玩家所带枪的 H 零件；第一次画格子时解码 I 零件；开工作台时解码 W 零件 | 每页一份 | W 零件随工作台关闭释放 |

- 上下文恢复：组合图都是 Canvas 2D 画的，作为纹理源的 canvas 一直留着，Pixi 恢复时自己重新上传，和现在的图集页一样，不用重画。不能用 RenderTexture 或只存在显存里的图做组合，恢复后会丢。
- 20 次往返（进出工作台、换预设、出击和撤离）后，三个缓存都不超过上限，图集页数不涨，Pixi 托管槽不涨。这是 M2-10 和 M5-02 的验收；可以照 `scope.ts` 的 `lifecycle.renderTextures` 加一个组合纹理计数。

### 4.4 不预生成

- 只在用到时组合：玩家拥有的枪、当前预览、正在看的预设。构建时和启动时都不生成，不把 20×100 的组合打进包里。
- 测试不渲染全排列。2000 个枪型×单件关系只做挂点覆盖检查：每个合法组合在三种输出里都找得到挂点（枪本身或父件），零件不越界，算出的组合不超过第 2 节的上限。只有代表配置（原厂、每枪两种配装方向、最长和最高的配置）真正渲染比对。

## 5 配件图标用 PNG

建议 Sol 交 PNG，每件一张 24×24。32 像素场合居中放，格子图用默认 24×24。理由：

- 数量：100 件程序画要写约 100 段画法。现有 30 种物品的画法（`items.ts`、`inventory.ts`）已有三百多行密集代码；再由代理写 100 段，风格容易跑偏，审起来也费劲。
- 一致：图标和 I、W 里的零件是同一个东西，同一个人一起画最不容易对不上。
- 体积：一张 24×24 的 PNG 约 200–250 字节，100 件约 25 KB（内联后约 33 KB）。程序画两种尺寸的代码量差不多，甚至更大。
- 工作量：一件只画一张，32 像素居中，省一半。
- 检查：`test:art` 的非空、无半透明、互不相同照样适用。

代价是多一条素材管线和清单（第 7 节）。旧的 30 种物品继续程序画，不动。新枪的 Q 方图也交 PNG。

## 6 体积预算

### 6.1 现状

- 本分支提交的 `dist/index.html` 和 main `4141503` 是同一份：7,071,165 字节，即 6.74 MiB（构建日志里的 “MB” 其实是 MiB）。`docs/release-manifest.json` 记的也是这个数。
- 10-22（main `2bac4fb`）是 5,720,996 字节。增长主要来自 #91 的县域图（13 张 WebP，原始 946,882 字节）。
- 内联的图片和字体 base64 共 5,486,600 字符，占整包 77.6%。原始字节：开场 PNG 2,300,486，县域 WebP 946,882，标题 362,315，商场 252,498，院子 127,709，沿海 79,174（七张持握图合计 1,663），字体 44,956。其余约 1.58 MB 是脚本、样式和页面。
- 便携 ZIP 4,567,427 字节。base64 的图片压进 ZIP 后约等于原始字节，所以 ZIP 的增长约等于新增图片的原始字节。
- main 没有整包上限。#81（草稿）的 EN-04 诊断定了 HTML ≤ 8 MiB、便携 ZIP ≤ 5 MiB；它当前 head `71cf986` 是 7,986,545 和 5,237,293 字节，只剩 402,063 和 5,587 字节（第 9 节第 1 条）。

### 6.2 估算和上限

按单张优化后的 PNG 估。小图的字节大多是 PNG 的固定开销。

| 批次 | 文件 | 原始字节（估） | 上限 |
| --- | --- | --- | --- |
| M2 样板 | 115 | 约 30 KB | 40 KiB |
| M3 第一波 | 约 270 | 约 75 KB | 88 KiB |
| M3 第二波 | 约 290 | 约 80 KB | 96 KiB |
| 合计 | 约 675 | 约 185 KB | 224 KiB |

- W 约占一半字节。
- 把零件按枪和输出无损拼成图集（像 #81 的 `scripts/pack-coast-art.py`），能省掉大部分 PNG 固定开销，合计估计降到约 120 KB。原 PNG 和哈希仍是权威，图集每帧记来源哈希。
- 上限 224 KiB（229,376 字节）指内联进 HTML 的改枪图片原始字节，不论是单张 PNG 还是打包后的图集。base64 后约 299 KiB。

### 6.3 构建怎么量

加在 `scripts/build.mjs`，和现有商场、院子的检查同一写法：

1. 生成的导入模块里的文件和 `assets/gunsmith/manifest.json` 一一对应。
2. 每个文件的 SHA-256、PNG 头里的宽高（`readUInt32BE(16)`、`readUInt32BE(20)`）、字节数（`bytes` 字段）都和清单一致。
3. 合计超过 229,376 字节时只在日志里提醒，不停止构建（2026-10-24 评审：整包不设硬上限，以能正常运行为准）；日志打印“改枪美术 N 个文件、X KiB / 224 KiB”。
4. 每批交付在 README 和 PR 里报本批字节和累计字节。超出本批上限要写明原因，这是开场动画的先例（[开场计划](../OPENING-CUTSCENE-PLAN.md)第 5 节）。

## 7 交付规则

### 7.1 文件和命名

- 每个零件、每种输出一张 PNG（RGBA 或索引色，sRGB，Alpha 只有 0/255），不拼图集。
- 运行图放 `assets/gunsmith/v1/`。id 全小写，用连字符，带版本后缀：
  - 机匣和原厂件：`gs-<枪型>-receiver-<输出>-v1`、`gs-<枪型>-<插槽>-factory-<输出>-v1`；
  - 配件：`gs-<编号>-<输出>-v1`，例如 `gs-o03-h-v1`；只给某几把枪用的变体加枪型，例如 `gs-h04-h-akb103-v1`；
  - 方图：`gs-<枪型或编号>-q24-v1`、`gs-<枪型>-q32-v1`；手套：`gs-glove-rear-h-v1` 等；
  - 输出代号：`h` 持枪，`i` 格子图，`w` 工作台，`q24`、`q32` 方图。
- 修改时出新文件、升后缀（`-v2`），清单写 `replacesSha256`，旧文件从清单删掉。运行时的键去掉后缀，像开场动画的 `scripts/opening-assets.mjs`，代码不用跟着改。

### 7.2 清单

`assets/gunsmith/manifest.json`，每张图一条：

| 字段 | 内容 |
| --- | --- |
| `id`、`file`、`w`、`h`、`bytes`、`sha256`、`revision` | 身份、尺寸、字节、哈希、修订 |
| `output` | `held`、`inventory`、`bench`、`icon24`、`icon32` |
| `gun` | 机匣和原厂件写枪型 id；配件写 null，只有给某把枪单画的变体才写枪型 |
| `item` | 配件编号（如 `O03`），方图写枪型 id 或配件编号 |
| `role` | `receiver`、`factory`、`part`、`glove`、`icon`；`bare` 是旧枪去掉画死的手的持枪图（M3-07），只给地上和 HUD 武器卡用 |
| `slot` | 装在哪个挂点（第 3.3 节的 id）；机匣和图标写 null；手套写 `gloveRear`、`gloveFront`、`gloveForegrip` |
| `anchor`、`mounts` | 自己的锚点；自己提供的挂点，如 `{ "top": [12, 0] }` |
| `grip`、`bore`、`forward` | 只在 H 机匣上 |
| `tip`、`hand`、`beam` | 枪管和枪口件、护木和前握把和手枪机匣、战术设备 |
| `layer` | 不按默认层序时才写 |
| `colors` | 不透明颜色数，自查用 |
| `source`、`sourceRect`、`exportMethod` | 来源和导出方法，同商场、院子清单 |

顶层写 `schema`、`revision`、`batch`、`totals`（文件数和 PNG 字节合计，开场清单的写法）。清单里不写玩家看得见的中文。

### 7.3 导入步骤（Opus，M2-10）

1. 只把清单列出的 PNG 和清单本身复制到仓库 `assets/gunsmith/`。不复制 `source/`、`preview/`。
2. 新增 `scripts/gunsmith-assets.mjs`（照 `mall-assets.mjs`）：核对哈希、宽高、字节、id 唯一、各角色的必填字段、锚点在画布内，生成 `src/art/gunsmith-assets.ts`（导入和元数据）。
3. 把新脚本登记进 `scripts/script-inventory.mjs` 的 tool 组，否则 `check:ci` 会失败（#91 遇到过）。
4. `pnpm build` 复核清单并检查预算；`pnpm test` 和加了改枪图的 `test:art` 通过后 `pnpm package`；生成物不提交，CI 自己构建。
5. 不用 `coast-import-assets.mjs`。若 #81 的无损图集已在 main 上，M2-10 决定改枪图要不要并进去。

### 7.4 字体

- 贴图上没有字，素材不带来新字。
- 新枪名、配件名、插槽名、拒绝原因都写在 `src` 的代码里。`scripts/font-characters.mjs` 扫描 `src` 下的 `.ts` 和 `.css`，缺字时构建报 “Regenerate the embedded font for: …”。
- 补字用 `scripts/subset-font.py` 和固定的上游 TTF（SHA-256 `9c699de0…`），重做 `assets/fonts/bincov-text.woff2` 和 `manifest.json`。这是 M2-12 的事；文案照 [COPY-GUIDE](../COPY-GUIDE.md)。
