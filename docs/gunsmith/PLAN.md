# 改枪系统总体计划

本次设计为《逃离滨科夫》建立 20 种枪械、100 种配件的改装体系，让搜到的零件能改变下一局的准备与战术。建议采用完整枪本体加可拆配件的中等深度模型，保留十分钟行动、格子背包、回站整备、失败损失和单文件离线的现有节奏。

用户已明确的目标是参考现实枪型、直接使用原型号（2026-10-09 更新）、达到 20 枪与 100 配件，并先制定计划。以下枪型清单、改装深度、弹药分组和实施安排均为待讨论的设计方案；阶段推进不会把最终目标缩减成早期样板数量。

初稿日期为 2026-10-07；2026-10-09 按 PR22 重做修订。已接受基线为 main `8355b857736df7fe471301d61208c25e2b7f9d61`；PR22 的本地实现作为后续接口依据，尚未合入主线。配套文件为 [二十种枪械目录](WEAPONS.md)、[一百种配件目录](ATTACHMENTS.md) 和 [PR22 衔接与阻塞](PR22-INTEGRATION.md)。

## 0 排期与开工条件

改枪排在 [PR #22](https://github.com/xuys2025/escape-bincov/pull/22) 完成之后。本轮只交付可审阅的文档；所有实现阶段，包括 M0 的代码原型、素材生产与接口修改，均等待 PR22 收尾并合入 main。PR22 远端当前有合并冲突，本地重做和补充修复尚未推送；这些由 PR22 原任务收尾。

PR22 完成后，先 fetch 最新 main，核对最终 Runtime/视图契约、存档版本、库存和音频实现及原任务验收结论，再确定 M0 基线。不能仅因 PR22 的早期文档合并或旧 CI 通过就宣布依赖解除。具体阻塞、复核项和验收责任见衔接文档；未获后续实施指令前停在文档交付。

不预先承诺日历开工日，也不沿用 PR22 的三工作日估算作为改枪工期。M0 验证迁移与完整样板后再估算后续阶段；最终交付仍为 20 枪和 100 配件。

## 1 命名与原创素材

按用户 2026-10-09 的最新要求，枪械直接使用 G17、M1911、MP5、AK-74、M4A1 等原型号，不再插入 B。旧三枪保留旧式手枪、双管霰弹枪、半自动卡宾枪的现有名称。本次只更新显示名称，计划中的内部 ID 保持不变。

现实枪型用于轮廓和使用定位参考；标识、说明、像素画和音效由项目制作。配件采用滨机、北堤、盐湾等虚构系列暂名，不直接使用现实厂家标志、塔科夫素材、图标、声音或整套商品文案。

使用原型号是本次命名决定，不构成已获授权的结论。名称问题可能涉及商标，图形、音效等还可能涉及版权等不同权利；具体边界取决于发布地区和使用方式。USPTO 对商标混淆的说明明确考虑读音、外观、含义和整体商业印象。正式对外名称应再做相应核查。来源：[USPTO 商标混淆说明](https://www.uspto.gov/trademarks/search/likelihood-confusion)、[WIPO 游戏及电竞知识产权说明](https://www.wipo.int/en/web/sports/esports)。

不以“塔科夫的所有枪都已得到授权”作为本设计成立的前提，也不对其具体授权情况作判断。

## 3 玩家循环和改装深度

玩家从老栓或战利品中得到一把完整枪，查看适配配件，回站预览改装，确认钱物及重量变化，再带入下一局。捡到配件时能够立即知道“适合哪几把枪”“仓库是否有适配枪”和“需要哪个基座”，减少反复翻表。

每把枪的原厂结构属于枪本体，原厂状态始终能正常使用。100 种配件是额外拥有的独立物品，安装后成为这把枪的子物品。拆下改装模块恢复原厂状态；原厂结构不额外生成可出售物品，也不计入 100 种。这样既能形成配装取舍，也能避免玩家捡到缺一枚小零件就完全无法使用的残枪。

正式首版提供十类改装：瞄具、枪口、枪管模块、护木、枪托、后握把、前握把/支撑、供弹模块、战术设备、基座/转接件。不同枪开放不同位置，固定枪托或双管供弹结构不会凭空多出相应插槽。

完整拆装建议在水产站进行。行动中可以查看配置、拾取、携带、转移和更换完整枪械；局内改装、逐发压弹、零件损耗、卡壳维修、口径转换与网上交易暂留后续。基础改枪入口不要求玩家先进入 RPG 地图；可行走基地的工作台打开同一界面，高等级工作台制作配件属于独立后续扩展。

## 4 二十枪与六类游戏弹药

枪型分配为 4 手枪、4 冲锋枪、3 霰弹枪、5 步枪、2 精确步枪、1 栓动步枪、1 轻机枪。完整候选及角色差异见 [枪械目录](WEAPONS.md)。

建议首版保留现有三种弹药，并增加三种，共六种游戏弹药组：

| 游戏弹药组 | ID 方向 | 覆盖方向 |
| --- | --- | --- |
| 9 毫米弹 | 保留 ammo9 | 旧手枪、G17、P226、MP5、Vector 9mm |
| 霰弹 | 保留 shell | 三种霰弹枪 |
| 卡宾枪弹 | 保留 ammoR | 半自动卡宾枪、两种 AK、M4A1、AUG、RPK |
| 重型手枪弹 | 新 ammo45 | M1911、UMP45 |
| 轻型高速弹 | 新 ammoPDW | P90 |
| 精确步枪弹 | 新 ammoHeavy | SVD、M14、M700 |

这是适合十分钟资源循环的虚构弹药分组，不宣称对应现实口径或弹匣互换。若以后采用严格现实口径，再扩展弹药表及迁移；不要现在让新手面对二十把枪和大量仅适用一枪的子弹。首版同一组只有一种基础弹，不同时叠加穿甲、弹壳、弹头等级。

## 6 属性如何影响二维游戏

玩家面板显示火力、精度、控制、操控、供弹、重量和声音暴露。展开详情再展示具体值、变化量和适用条件，避免只有难理解的总评分。

| 属性 | 在游戏中的实际效果 |
| --- | --- |
| 单发伤害和射击节奏 | 主要来自枪型及弹药组；普通配件不直接堆叠伤害 |
| 基础精度 | 静止稳定后单次射击的散布 |
| 连续控制 | 连续射击时散布增长和停火后的恢复；首次加入有边界的累积状态 |
| 操控 | 从移动/切枪到稳定精瞄的时间，不能只改说明文字 |
| 有效距离 | 弹丸的游戏距离上限；不是增加穿墙能力 |
| 供弹 | 有效弹量、换弹时长和分次装填行为 |
| 重量和占格 | 完整枪本体、附件和弹药各计一次，参与现有负重规则 |
| 声音暴露 | 吸引敌人的游戏范围；消音后仍会出声，近处敌人仍能反应 |

建议先用下列调参护栏做样板：配件带来的散布/后坐改善不超过原厂的 40%，操控时间不短于原厂的 65%，有效距离增加不超过 25%，消音后的声音吸引范围不低于原厂的 40%。这些是待实测的设计边界，不是已验证平衡；角色技巧和状态效果另外受各自边界限制。

计算采用固定顺序：原厂值 → 互斥模块替换 → 同维度增减汇总 → 配件护栏 → 一次角色状态修正 → 精瞄/移动/连续射击状态。保存部件和必要运行状态，最终属性从它们重算，不信任备份中伪造的“最终伤害”。

连续射击状态、剩余装填时间、设备开关和其他会影响战斗结果的状态随检查点保存，刷新不能免费恢复控制。移层仍遵守先结算一次来源层弹丸再冻结的已接受规则。

## 7 瞄具和战术设备的二维表现

瞄具首先改变稳定和操控。PR22 样板已有精瞄时的相机前探，新的瞄具在该相机体系中扩展，不能再叠一套独立相机或机械套用初稿的 1.25 倍视野。M0 以 PR22 最终接受的观察范围为基线，验证有限前探或远向观察方案，再确定统一上限。物品使用近距、中距、远距和双档名称，界面显示实际收益，不标注无法兑现的真实六倍画面。

准星、鼠标世界坐标和手机瞄准方向必须使用 PR22 接受的同一转换，覆盖脚底坐标、持枪高度、方向缩短、相机前探和面板停靠偏移；同时验证保留的 Phaser 路径。视觉枪口与逻辑弹丸起点分别管理，长枪管或消音器不得把弹丸出生点移过墙体。退出精瞄、关闭面板、切层、死亡、回站和关闭动态时，相关相机状态正确恢复。倍镜不显示墙后或其他楼层的目标，不用大块黑圈遮住俯视战斗。

激光只影响有效距离内的腰射；灯光帮助识别已有视线内的可交互物，不透视物资内容或敌人。两者开启有可感知的视觉暴露代价，判定服从同层与视线规则。首版不引入额外电池消耗经济，设备有开关并保存状态；每枪最多一个激光效果和一个灯光效果。

## 8 背包与枪械实例

一把枪有唯一 UID、枪型 ID、配件树、设备开关和必要的持久状态。已安装配件也保留自己的 UID，并且只能位于该枪内部或某个库存中，不能同时存在两处。枪械和配件均不堆叠，避免两个不同配置的同型号枪被合并。

装备、卸下、放入仓库、尸体/箱子转移、丢到地面、跨层、撤离、死亡和备份均搬运同一实例。现有卸枪先退出弹药的行为继续采用，卸出的普通弹和救济弹分别守恒；不能在移动枪时重新构造一把原厂枪而丢失配件。

成枪占格由基础形状与明示的附件边界决定。消音器、长模块或大型供弹可增加宽/高；预览先展示新形状。原位放不下时让玩家选择新落点或取消，不能静默删掉物品。最长合法首版组合需能够通过 6×5 背包和交易流程，若本次位置不足仍应正常拒绝。

安全箱按完整实例实际形状和既有物品规则判断。装在枪上的附件随枪一起保留或损失；散件进入安全箱则按其原有保护规则处理。不能因附件藏在枪内而漏计重量、占格或价值。

换小弹匣造成的多余子弹先在候选库存中卸出；没有空间则整次改装不提交。首版弹匣是决定供弹规格的配件，不另保存每个备用弹匣的逐发装填内容，仍用现有背包散弹补充模式。

## 9 原子提交与存档迁移

改枪流程为选枪 → 创建预览候选 → 验证枪与配件的实际所有权 → 检查依赖/冲突/弹量/格位 → 一次保存 → 展示成功。预览、取消、切换筛选都不写入真实钱物。确认时重新核对修订号、原枪及配件位置，拒绝过期预览。

旧枪迁移成原厂实例，数量、弹药、救济来源、位置、现金、任务和活动行动结果不变。新分配的 UID 来自受控迁移分配器；不消耗战斗随机数，不因重复加载重复生成。旧原始字节按既有策略保留。

主档键继续使用 escape-bincov.session.v2。新封套、档案、检查点和备份的版本号在 PR22 合并后由 M0 核对并分配，不提前占用初稿建议的 session v5 / 档案 v3。还需用 PR22 最终保存的 Runtime 行动样本验证恢复与回滚。必须覆盖旧已结算档、旧已结算备份、活动经典海岸、活动多层、待保存结算，以及内含迁移备份的记录。新旧版本、扩展内部组件版本应分别定义，不能只把顶层版本数字加一。

读取时递归校验枪型、配件 ID、数量、全记录 UID 唯一、树深、节点数、合法依赖、冲突、运行值范围、弹量和实际占格。未知版本拒绝覆盖。旧客户端面对新封套必须安全拒绝；新版导出的完整备份也必须完整恢复配件。

保存失败恢复枪、拆装零件、弹药、钱物、世界容器和设备状态；结算失败继续保留同一候选重试，不能重复授予整枪或附件。交易、防冲突和导入的保护方式复用 SaveSession，不另建第二个独立的改枪存档。

## 10 商店和战利品

老栓保留现有统一结算。上方目录改为可检索/按类别与适配枪筛选的商品浏览区；待买、待卖和仓库仍支持格位预览。待买/待卖逻辑容量需覆盖最大合法成枪，不能只把原 4×3 的界面拉宽。

展示“适配当前枪”“已拥有”“缺少基座”“本次会拆下什么”。出售成枪时列出枪与每件附件的价格，总价按真实可售组成计算；也可先回工作台拆出自留配件。价格不能只取基础枪的 sell 值而吞掉附件。

救济属性逐物品保留。救济枪本体和救济弹不变成可售资产；后来购买的正常配件可拆回后出售。销售预览明确说明无法出售的组成，拒绝整件包含受限组成的销售，不自动剥离或销毁它们。

获取分三层：入门枪与基础件稳定供应；常规件随任务/行动进度进入轮换货架及分区战利品；稀有枪和精密件通过高风险物资点与后期货架取得。商人轮换由已保存的进度/种子驱动，不靠重复刷新页面刷货。

价格以现有 700 初始现金、320 旧手枪、1200 旧卡宾和任务奖励为起点试算：基础件可先试 40–150，常规件 150–450，稀有件 450–1200 游戏货币。目标是一次正常撤离有机会完成一次有意义的小改装；完整高端配装需要多次行动。实际价格要根据真实结算收入校准，不把这些初值写成已平衡结果。

100 件按类别、区域和进度分池，不全部平均塞进现有掉落表。保留行动原有 60 份原始物资预算及任务/食药供给，配件从武器/贵重等相应份额重新分配。至少测量连续二十局的弹药断供、无用配件积压和任务物資完成率，再确定权重。

## 11 工作台界面和预设

工作台在 PR22 最终接受的界面规范上扩展，复用既有库存事务；基地界面与新的沿海库存面板都要展示同一枪械实例及组合属性。保留 PR22 物品全名、短屏字体适配、拖动影子定位与取消清理的修复，不能复制早期面板模板覆盖它们。桌面沿用接受后的颜色、像素字体和格子风格。左侧是枪械与预设，中间是可放大的原创枪身及插槽，右侧是适配件与属性比较，底部显示待安装/待卸、重量、容量和确认/取消。点击插槽直接筛选可用件，也能切到“查看未拥有的适配件”。

手机采用枪身/配件/属性分页，确认和取消保持固定可见，点击完成全部核心操作。拖拽只是桌面快捷方式；旋转、退出和重新选枪保留或明确取消候选，不能因为弹窗遮挡失去返回路径。

预设只保存枪型和配件定义，最多十套；不保存可反复领取的实体 UID。应用时匹配现有库存，不自动购买、不凭空补齐，缺件明确列出。缺件预设可保存供收集，只有完整且合法的实体配置才能应用。

两个示例方向：
- 轻快 M4A1：短护木、轻枪托、开放红点、快换匣，适合走动与短时交战，弹量较少。
- 稳定 M4A1：长护木、稳枪托、稳定握把、制退器，持续射击更好，负重、举枪速度和声音暴露更差。

首版不把改枪成功强行绑定购买或材料消耗；组装本身免费，成本来自玩家取得的枪与配件。后续配件生产可以接入工作台等级和既有队列，需另定配方及经济范围。

## 12 美术和声音生产

需要 20 套可辨认的枪身基础轮廓、100 个配件图标与可组合展示。生产规格先对齐 PR22 最终素材管线，区分工作台大图、共享库存/地面图标和 2.5D 角色持枪三种输出；不以同一张图简单放大代替全部场景。旧三枪沿用已接受资产，不能只改色填满目录。

PR22 当前采用武器图中的手套、运行时袖管、握把旋转轴、前手距离、视觉枪口和纵深缩短。新增枪械及配件组合要给出相同语义的挂点；前握把、枪托、枪管变化后，手臂连接、镜像、前后遮挡和枪口火一致。具体尺寸与图层规格在 M0 按最终方案确定，不重画 PR22 已接受的人物和场景。

库存与地面沿用共享物品图标入口，组合外观由配置标识缓存；工作台大图展示插槽与附件差异。纹理缓存键至少区分枪型、配件配置、素材版本和需要的角色配色，避免同型号两把枪串图；设上限并按 PR22 生命周期释放。不预生成 20×100 的全部组合，换装、换层、上下文恢复与 20 次往返均检查资源。

声音沿用 PR22 接入的共享 SynthAudio 与事件驱动，保留声像、距离衰减、暂停恢复和声音队列修复。开火事件提供有效配置对应的音色与消音状态；前端播放声音，Runtime 决定敌人听觉半径，二者读取同一配置。不能仅改播放音量就声称消音器改变了 AI。视图事件按原 seq / epoch 规则消费，读档、重绘和结算落幕不重复开枪或发奖。所有资产继续内联、离线运行。

## 15 验收清单

1. 20 种可用枪型、100 种有效配件计数准确；每件有图、有功能、有代价、有获取路径、有合法适配。
2. 接口依赖可解释，非法安装、重复插槽、循环树、未知 ID、超深树、重复 UID 均被拒绝。
3. 同型号两把不同改装枪在装备、卸下、跨库、买卖、世界丢取、跨层和读档后保持各自配置。
4. 预览取消不改钱物；更换护木/基座时子件不消失；空间不足或缩容卸弹失败时完全不提交。
5. 普通及救济枪、附件、弹药来源守恒；反复装拆、买卖、死亡或结算重试不能复制物品、刷钱或洗掉救济属性。
6. 原厂旧三枪迁移无损，活动经典/多层/待结算档均有样本；未知和损坏档安全拒绝。
7. 实际开火、HUD、换弹容量、背包重量、价格及备份校验读取同一配置，瞄具与设备效果真实存在。
8. PR22 接受的新沿海显示/Runtime 与仍保留的经典海岸、居民楼、商场路径都能完成获取、装备、战斗、结算、恢复流程；同配置的容量、伤害、散布、负重、噪声和回滚一致，离层弹丸规则保持原语义。
9. UI 覆盖 1280×720、1920×1080、844×390、740×300、640×300、390×844；核心操作不依赖悬停、右键或拖拽。武器和配件名称可读、影子跟随指针、面板重绘/关闭无残留，并保留 PR22 相应回归。
10. 多次预设切换、进出工作台与十分钟行动后，缓存数量和节点不持续增长；相同设备独立测量，建议 P95 帧耗时回退不超过基线 10%，超出即定位优化。
11. 实际真人能区分轻快、安静、稳定和大容量配装的用途。人工判断与自动统计分开登记。
12. 代码改动执行 pnpm test、pnpm package、相关存档/库存/商店/输入/多层/美术回归及 test:portable，并以最新 CI 为准；新增 gunsmith 规则和浏览器专项。同时保留 PR22 最终样板、握持/瞄准、音频、上下文恢复与 20 次往返门禁，最终命令以合并后的 package.json 和 scripts 为准。保存失败、普通离线入口和备份测试是必须项。

详细组合不做二十乘一百的盲目全排列。对所有 2000 个枪型/单配件关系验证预期，再覆盖每条依赖、每类冲突、合法代表配置、极端容量/重量、故障与迁移，并用固定种子生成多种合法组合做往返守恒测试。

## 16 建议先讨论的设计选择

建议保留这三项首版选择：完整原厂枪加模块化附件、六种虚构弹药组、完整拆装回站完成。它们把开发和学习成本集中在真正可感知的配装差异上。

如果用户更希望“逐零件拆到空机匣”“严格区分现实口径”或“行动中拆枪取件”，应在 M0 修改数据和交互范围，再开始实现；20 枪与 100 配件的最终数量目标仍保留。
