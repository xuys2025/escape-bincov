## 已调整的冲突点

| PR22 已有或正在重做的部分 | 初稿直接实施会产生的问题 | 改枪计划采用的处理 |
| --- | --- | --- |
| Runtime 负责模拟，presentation 发布只读帧，Pixi 负责展示 | 只改 game.ts 会使新旧入口使用不同武器属性 | 新旧逻辑共用有效配置计算；Runtime、HUD、背包重量、装填、保存校验一并接入 |
| WeaponLook 只含 pistol / shotgun / carbine / knife / club / claw / rifle | 新增型号直接转成该类型，显示会落到旧通用轮廓，事件也分不清配装 | 分离枪型 ID、实例 UID、外观配置和音色配置；保留敌人及近战路径，字段名于 M0 固定 |
| 视图使用脚底坐标、AIM_H、前探镜头与面板停靠偏移 | 另加瞄具相机会造成准星与弹道错位，手机触点也偏移 | 使用 PR22 最终坐标转换和相机；取消初稿独立 1.25 倍假设，加入精瞄、短屏、停靠面板和换层用例 |
| 手套在武器图上，袖管运行时连接；视觉持枪长度随朝向缩短 | 直接复用旧俯视枪图会出现手臂悬空、枪口火与枪身脱离 | 配置握把轴、前手、视觉枪口与组合挂点；枪管变长不擅改逻辑弹丸出生点，验证贴墙射击 |
| 原物品图标被新库存和地面共用，缓存按武器类别和手套配色生成 | 只按型号缓存会让不同配置串图；每次配装又可能无限增纹理 | 共享图标入口按配置更新，持枪缓存含配置和资产版本；继承生命周期清理与上下文恢复 |
| 第六轮库存全名及拖动影子修复，基地 ui.ts 仍存在 | 复制早期模板会带回文字截断和面板溢出；只改一套入口会漏实例 | 新旧库存都展示同一实例；保留全名、字号降级、根节点影子、取消清理及 U11/U12 类用例 |
| sound.ts 消费事件，共享 SynthAudio 已加声像与恢复期排队 | 重新播放音效会丢声或重播；仅降低音量不能改变敌人听觉 | 从有效配置发布音色/消音数据；Runtime 计算听觉，前端消费一次；保留恢复与声像回归 |
| 保存仍通过同一 SaveSession，PR22 尚有接口及边界复核项 | 提前指定封套版本和检查点结构，可能覆盖重做期间的最终协议 | M0 以最终版本重新分配格式；保留完整旧字节、原子提交、活动 Runtime/多层样本和失败回滚 |

视觉镜头后坐与逻辑散布分开：配件改变的有效控制参数由规则层计算，视图表现读取结果，不能再叠一次数值惩罚。设备灯光、激光、消音火焰及倍镜始终服从原有揭示权限；未揭示房间不因新增附件出现轮廓、光点或声音位置提示。
