# 射击基础调研与改枪前置样板

> 2026-10-22：本页是 Phaser 时期的调研，留作依据。下文的 M0-S 已由 [PR #39](https://github.com/xuys2025/escape-bincov/pull/39) 在 2.5D Runtime 上重测并实现（S0–S5 与试枪场），维护者试玩后选定“稳定”手感；现行射击规则以 #39 合入后的 `docs/SHOOTING-SYSTEM-REWORK.md` 和 `src/shooting.ts` 为准，第 6 节的四方分工已不再使用。改枪任务见 [任务与排期](TASKS.md)。

2026-10-12 核对 main `64505046fb737af195bc808d2f8e4274df21cf24`，续作原 PR #28。维护者已选择「品牌放详情」，并要求先解决射击缺少瞄准和控制感的问题，再做配件。本轮完成调研与排期调整，尚未改动射击实现。

当前已经有指向瞄准、随机散布和右键精瞄，但缺少连续开火后的枪口偏移、动态稳定过程以及能解释这些状态的准星。应先做一小套可试玩的射击基础，证明不同操作和参数能带来可感知的取舍，再扩充枪械与配件。弹量、换弹、重量等已有作用基础；精度、控制、操控类配件尤其需要补齐底层机制，不能只在说明里写百分比。

## 1. 当前代码与体验差距

| 项目 | 当前实现与依据 | 对体验的判断 |
| --- | --- | --- |
| 鼠标指向 | [scene.ts](../../src/coast-view/scene.ts) 的 `aimFromClient` 将鼠标转成世界坐标，修正 22 px 持枪高度；[Runtime](../../src/raid-runtime/runtime.ts) 每帧更新玩家朝向；旧 `game.ts`（已在 #64 删除）也按指针算角度 | 已有瞄准。仍需核对可见身体、准星、枪口与碰撞对应；两个方向正确不证明贴墙、各缩放和移动目标全部正确 |
| 扳机 | [样板输入](../../src/coast-view/input.ts) 与 [原输入](../../src/input.ts) 的桌面开火取按下边沿，触屏右摇杆外圈提供持续开火 | 旧三枪是半自动/双管，一次点击一枪合理；未来自动枪需有逐枪射击模式，不能一律改成长按连射 |
| 散布 | [武器表](../../src/domain.ts) 的全角分别为手枪 0.07、卡宾 0.035、霰弹 0.27 弧度；每颗弹丸取 `(random - 0.5) * spread` | 存在随机误差，但同状态下是固定锥形，没有随连续开火累积的散布 |
| 精瞄 | 右键立即将散布乘 0.35，降低移动速度并增加相机前探 | 有收益，没有举枪到稳定的时间过程；手枪、卡宾的腰射本来就很准，许多距离上难感到区别 |
| 角色状态 | [rpg.ts](../../src/rpg.ts) 的 `recoil` 根据技巧、精神、疼痛缩放散布 | 名称叫后坐，实际是精度系数，不是开枪后累积的枪口偏移。移动可能间接改变角色状态，不能说与精度完全无关 |
| 运动与恢复 | 射击公式不直接读取移动速度、急转幅度或连续射击状态，没有独立停步/停火稳定过程 | 缺少移动抢近点、停步打远点、短点射恢复的操作差异 |
| 后坐表现 | [scene.ts](../../src/coast-view/scene.ts) 开火事件推动镜头约 2–4 世界像素再衰减；[host.ts](../../src/coast-view/host.ts) 短暂放大准星 | 有反馈，没有 Runtime 管理的武器后坐状态。相机移动可能间接影响指针换算，但不能充当完整压枪机制 |
| 命中 | 有速度、射程的真实弹丸处理遮挡与碰撞；[shotIntersection](../../src/layer-transition.ts) 使用圆形目标 | 不是点击敌人自动扣血，也不保证随机散布下每颗弹丸经过鼠标点；需要让预期瞄准中心、可能落点与命中对应 |

## 2. 本轮实测及限制

摘要见 [diagnosis.json](evidence/shooting-20261012/diagnosis.json)。使用未修改主线的离线包，SHA-256 为 `2320bd31ef8a192e7e3ca2e1175e93742ba19001eb88ab4f9c44046503b88231`。

- Chromium 154、1280×720，真实菜单进入、种子 42、`sample=village`、晴天。测试驱动仅固定位置、冻结 AI、设置武器；实际鼠标输入下，两个位置的发布朝向都与坐标换算相符；按住左键 1.5 秒只开一枪；右键进入精瞄；间隔 400 ms 的两次点击产生两次真实开火事件。页面错误和外部请求均为 0。
- 隔离 Runtime 开火函数，三枪各做普通/精瞄 64 次触发，每次只重置弹匣和冷却便于取样。相同随机数下，角误差精确缩为 0.35 倍；开火函数不改变玩家旋转。此实验确认公式，不是连续实战、节奏测试或真人验收。
- 输入对象检查确认桌面按住不会持续请求开火，触屏右摇杆外圈则会，且摇杆瞄准期间不使用右键式精瞄。这需要双端共同设计，不能假定手机已有等价精瞄操作。
- 理想几何中，瞄准 320 世界像素（10 格）外、半径 14 的静止目标中心，不算墙、目标移动和 RPG 修正：手枪腰射最大横向偏差约 11.20 px，卡宾约 5.60 px，均小于目标半径。固定种子 1000 条射线分别全部与目标相交，精瞄后偏差缩为约 3.92 / 1.96 px。这解释了此距离精瞄可能没体感收益；不是实战命中率，不能推广到所有距离。霰弹射程与弹丸分布不同，不参与这个结论。

未测：真人手感、真实手机、所有视角/遮挡位置、敌人射击平衡。现有逻辑存在，不等于现有手感合格。本地测量首次以 Windows 路径传入 Node 的 ESM loader，启动前失败；改为 `file:///` 后运行通过，不是产品失败。

## 3. 一手开发资料

1. Battlefield 团队把输入到出弹响应、后坐与枪械差异、瞄准控制和实际试玩并列验证。这里据此建议先验证小型可玩射击样板，再扩目录，而不是靠参数表验收手感。[开发说明](https://www.ea.com/en-gb/games/battlefield/news/gunplay-and-movement-philosophy)
2. Six Days 团队明确区分镜头后坐与武器后坐，降低镜头扰动以保持画面，用动态准星表达精度，并校正不同瞄准方式的对齐。这支持将真实弹道状态与表现分开，让玩家读懂误差来源。[瞄准与射击更新](https://support.sixdays.com/support/solutions/articles/154000168459-devlog-update-notes-aiming-and-shooting)

两者均为第一人称游戏。这些是参考原则，以下俯视 2.5D 方案是本项目的设计建议，不照搬垂直压枪曲线、瞄准镜黑圈，也不限制 Opus 的技术和视觉选择。

## 4. 先做 M0-S 射击基础样板

建议旧三枪加计划内一把自动枪（优先 M4A1）的临时射击样本，可复用占位外观。先不生产二十枪/百件素材或完整商店、掉落、实例迁移；样本数据不得混入正式经济和玩家存档。通过后进入总体计划 M0 的实例/改装风险原型，最终 20 枪/100 件目标保留。

| 顺序 | 玩家应能感受到什么 | 共同验证内容 |
| --- | --- | --- |
| 1 指向与命中对应 | 鼠标所指是预期瞄准中心，能判断墙挡住枪；移动目标需要提前量 | 枪口、瞄准高度、相机前探、缩放、近墙与碰撞一致；准星表达误差范围，不用吸附目标或穿墙掩盖偏差 |
| 2 稳定过程 | 腰射适合近处，停步精瞄适合远处；快速移动、急转后短暂恢复稳定 | 移动/转向/精瞄进度决定准确度状态；耗时先调样板，避免过重惩罚和输入迟滞 |
| 3 可控制的后坐与散布 | 连续开火更难控制，短点射或停火能够恢复 | 后坐改变实际发射方向，散布是方向周围的不确定性，两者独立；由样板验证适合俯视的偏移/补偿，不移动系统鼠标，不只增加随机大抖动 |
| 4 按枪型开火 | 半自动按一下打一发，自动枪按住连射、释放停止 | 枪型定义模式与节奏；冷却内点击是否短暂缓冲需明确定义，不能无限排队或松手后延迟连发。双端射速同规则，暂停/失焦/面板取消后不粘枪 |
| 5 看得懂的反馈 | 能区分没稳住、连射失控、射程不足和墙挡住 | Runtime 发布准确度、稳定进度、后坐；Opus 决定准星、握持、镜头、弹着与声音。减少动态效果不改变逻辑散布 |

新增计时与战斗状态由逻辑管理，新旧局内调用共同计算。保留角色状态修正、弹药来源、暂停/卡顿处理；明确状态如何保存恢复，不能通过刷新、换层或切枪免费清除控制代价。

## 5. 再证明配件有意义

先用少量临时参数配置作对照，不提前实现获取和交易：

| 配件方向 | 必须支持的实际差异 | 取舍例子，待调参 |
| --- | --- | --- |
| 瞄具 | 精瞄稳定时间、可读性及已允许的观察范围 | 稳定首发与近距快速切换之间取舍，不叠无限视野 |
| 枪托、握把、制退器 | 真实方向偏移、连续散布和恢复 | 持续控制更好，但重量、操控或声音暴露更差 |
| 枪管 | 稳定后的精度与有效距离 | 远距有优势，近处转移和携带有代价 |
| 弹匣 | 容量、换弹和携带负担 | 少换弹与重量/装填耗时之间取舍，不需要全部后坐功能才有基本价值 |
| 消音器 | 实际声音传播和敌人察觉 | 更隐蔽但更重、更长，不是关掉声音就算实现 |

若同枪两套配置只有面板数字变化，实际射击与操作没有区别，就继续调整基础，暂不扩量。不能故意把原厂枪改得失控来制造配件需求。目录收益均为待实现承诺，不是当前能力。

## 6. 交接与验收

1. **Astra 先定逻辑边界与最小契约：**负责后坐、动态散布、稳定计时、开火模式、存档与新旧路径一致，提供可重复参数样本；不预定前端布局和效果。
2. **Opus 做可玩样板：**主导指向、准星、持枪、镜头、触屏和反馈；与 Astra 迭代状态接口和参数，不在视图另建命中规则。
3. **Sol 独立验证：**测真实弹着、输入取消、节奏、暂停/恢复与故障；正式图等 Opus 给出挂点和规格后再生产。模拟手机不能替代真机真人。
4. **维护者试玩、主调度收口：**确认操作与代表配置有区别，再进 M0/M1/M2；自动统计和主观手感分别记录，按具体责任退回，不扩大无关回归。

样板需覆盖：

- 同位置、朝向、武器下腰射/精瞄、静止/移动、单点/连射/停火恢复。在各枪射程内的近中远目标上记录命中分布、首发响应、稳定及恢复时间，另测射程外行为。
- 固定输入与种子，30/60/120 渲染帧率下逻辑发射次数、弹着与恢复一致；双端受同一节奏约束。视觉回弹不改写随机数、不决定命中。
- 两套代表配置有可重复收益与代价，基础枪仍可正常玩；具体平衡阈值由样板实测决定。
- 八方向、近墙、门窗、缩放与前探下准星和命中对应；隐藏房间、换层和读档不泄露目标，长枪外观不让弹丸出生点越墙。
- 保存失败、暂停/切窗、刷新和换层不复制弹药、不跳过冷却/恢复、不丢状态，离线能力保留。
- 真人能理解「为什么这一枪没中」「这套枪适合什么打法」；当前调研不先签收新手感。
