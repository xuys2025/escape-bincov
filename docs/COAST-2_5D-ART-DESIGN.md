## 1. 目标、范围与当前事实

### 1.1 设计目标

让玩家能够从轮廓、立面、接地阴影和遮挡关系读出街巷、室内与港口空间，同时清楚识别可走区域、门窗、敌人、战利品与撤离入口。借鉴 ZERO Sievert 的俯视像素表现，保留滨科夫的虚构中国沿海县城、台风灾后、盐蚀与赤潮题材，不复制其地图、角色、标志或成品素材。

本文的“2.5D”专指二维渲染形成的体积感，不引入三维引擎、菱形等距投影、透视缩放、旋转镜头或新的高度战斗规则。视角参考来自 [ZERO Sievert 官方商店展示](https://store.steampowered.com/app/1782120/ZERO_Sievert/)，其中官方称其为 top-down 游戏；本文的分层、锚点与像素数值均是本项目拟议方案，不是该游戏的技术参数。

### 1.2 范围

- 覆盖城中村、水产市场、潮汐观测站、旧渔港、海堤泵房，以及沿海地图已有建筑所关联的室内和楼层空间；现有小楼层沿用各自尺寸，不扩大成 72×52 格。
- 沿海主地图保持 72×52 格、每格 32 逻辑像素，即 2304×1664；保留现有道路、建筑占地、门窗、楼梯、出生点、物资逻辑点和撤离位置。
- 人物与敌人的直立表现、尸体及世界内物资属于视角衔接；不在本任务重画库存图标、战术 UI、商场、基地或主菜单。
- 不改任务、经济、数值、门窗交互、楼层切换、潮汐时间、AI、弹道与命中规则，不借美术重构新增建筑、障碍或可探索区域。
- 本文独立于已合并的主菜单 PR #21：主菜单的视差、连续采样和光照方案不能直接作为局内实现规则。

## 2. 视角、坐标与遮挡

### 2.1 地面与立面

地面保持横平竖直、无远近缩小。建筑占地仍是原逻辑矩形，立面从接地线向屏幕上方延伸；屋顶是占地上方的独立视觉层，不能把整栋建筑向上搬动后再用贴图边缘碰撞。

下图只说明位置关系，不按精确比例，也不是实际截图：

```text
屏幕上方
        ┌────────────屋顶────────────┐
        │                            │
        ├───────可见墙面／窗──────────┤
        │           门洞             │
地面    └────────接地线───────────────┘
                        ● 头
                       /█\ 身
                        ║
                        × 脚底 = 原世界位置
道路    ══════════════════════════════
屏幕下方
```

南向墙面是主要可见立面；北向墙显示墙顶与必要的内侧面，东西墙显示连续墙沿及内外侧差异。所有立面共用高度单位，不为了同时展示多个侧面把地图画成菱形。墙面上抬后的门窗外观必须指向原门洞/窗洞，不能把画面中的通路与逻辑入口错开。

### 2.2 人物与瞄准

- 地面逻辑坐标仍对应原角色位置；新直立人物的脚底在此落地。角色画布初始为 32×48，锚点按边界坐标记为 (16,48)，像素索引仍为 x=0…31、y=0…47；不可混淆边界坐标与像素索引。
- 身体按瞄准朝向选择东、东南、南、西南、西、西北、北、东北八方向；每个扇区 45°，中心分别对准八个方向。连续瞄准角保留，不按八方向量化子弹或近战方向。
- 身体图不整体旋转；武器与手臂分层表现连续瞄准，前后手关系随朝向切换。姿势、阴影和受击闪烁只改显示，不改变冷却、攻击范围或命中圆。
- 原逻辑坐标、射线起点和射击角是判定依据；枪口闪光与弹丸可见起点须与既有弹道校准，不能为了贴合新枪图偷偷改变真实发射点。
- 静止、移动、受击和死亡的外观状态由现有状态推导；首轮试样先验证八方向静态、武器关系和一组移动循环，再扩充动画，不把 AI 连续帧一致性视为已保证。
- 尸体使用单独平放素材，仍关联原实体与搜刮容器；不把直立人体简单旋转 90°当作倒地。

### 2.3 分层与脚底排序

| 层次 | 内容 | 排序与约束 |
| --- | --- | --- |
| 地面 | 柏油、混凝土、室内地板、海水、泥滩 | 缓存静态层；潮位材质随现有状态更新 |
| 地表细节 | 裂缝、盐渍、纸屑、浅水纹 | 只贴地，不覆盖角色关键轮廓 |
| 接地阴影 | 人物、道具、墙体投影 | 位于主体下方、随对象复用；不重复叠加烘焙长阴影 |
| 地面物件 | 尸体、散落物资、扁平杂物 | 保留交互来源和位置；不得画成高墙 |
| 立体对象 | 人物、箱桶、摊位、墙段、设备 | 以地面接触位置的 y 从后向前排序；同值按稳定实体/段标识排序 |
| 上部遮挡 | 屋顶、雨棚、高物体上部 | 独立遮挡与揭示处理，不能永久压住玩家和有效交互 |
| 世界特效 | 弹丸、火花、水花、枪口光 | 接受有效墙体/屋顶遮挡，不无条件穿透前景显示 |
| 交互与界面 | 已允许显示的名称、准星、危险及撤离提示 | 可读性优先，但不提供新可见性或穿墙目标信息 |

低矮立体物仍按接地点参加人物排序，只是遮挡高度较小；“低矮”不代表一律贴在地板上。长墙、连续柜台与大建筑按墙段/占地段拆分，不能用整栋建筑底边统一排序。接地高度和淡化阈值属于渲染配置，不能反向生成碰撞。

### 2.4 屋顶、墙体淡化与信息边界

基线房间遮罩会保留密封房间的覆盖；非密封房间在玩家位于内部，或接近房间且现有视线判断允许时揭示。后续必须复用该判断的语义；本文不把它扩大成全新视野系统，也不规定“距房间近就透视”。

1. 房间未满足现有揭示条件时，屋顶/遮罩继续遮住室内实体；不得因玩家靠近高物体而把整个室内层暴露。
2. 房间已允许揭示时，可隐藏屋顶上片并保留墙顶；遮住玩家或当前有效交互的前墙上片采用降低或像素抖动淡化，下部接地轮廓保留。
3. 首版墙体淡化采用固定像素覆盖图案，不对整场景模糊；仅作用于导致遮挡的墙段/高物体上部。未被现有规则允许显示的实体不增加轮廓、名字或穿墙高亮。
4. 可视上片的透明与门窗碰撞是两条独立链路：关门依然阻挡；窗户仍按当前规则处理移动、视线与子弹。隔窗搜刮/近战不能因素材透明而变得可用。
5. 出入门口、换层、刷新恢复或潮位切换后，从已提交世界状态重建显示；不保存“当前淡化了哪堵墙”作为新游戏进度。

## 3. 像素尺度、光照与色板

### 3.1 制作尺寸

所有尺寸均为整理后的逻辑像素，和 GPT Image 源图分辨率分开记录。

| 类别 | 首版规格 | 锚点与拼接 |
| --- | --- | --- |
| 基础地面 | 32×32 | 左上对齐地块；边缘可无缝重复 |
| 地面大型图案 | 64×64、128×128 | 拆回 32 格；标线不改变路径 |
| 墙体段 | 32×64 | 底部接地，上方容纳立面和墙顶；相邻段共用接缝 |
| 门窗模块 | 32×64；双格入口为 64×64 | 实际开口必须匹配原逻辑格，不因画布标准缩窄门洞 |
| 屋顶模块 | 32×32 基础、64×64 组合 | 区分中心、边、内外角；按现有建筑占地组合 |
| 人物 | 32×48 | 脚底 (16,48)；八方向共用基线 |
| 小型道具 | 32×32、32×64 | 在登记表明确地面接触点，不能只取不透明包围盒底边 |
| 大型道具 | 64×64、64×96、128×128 | 主体、阴影及遮挡上片可拆；细长船体按 32 的整数倍扩展 |
| 世界物资/尸体 | 沿用原占地语义，画布可按 32 扩展 | 保留原拾取距离和容器位置，不按画布大小扩张交互范围 |

采用最近邻检查原尺寸及 2×/3×放大；运行缩放沿用局内视口约定。不要用主菜单专用的高分辨率表面方案覆盖局内坐标。AI 大图的“像素画外观”不代表像素格准确：缩小后仍需校正轮廓、色阶、透明边、接缝和方向间基线。

### 3.2 基础色板

以下为首版目标色，不是对现有全部素材的机械替换。单件材质通常选 3～5 档明暗；危险提示等功能色不按环境色板强制降饱和。

| 用途 | 色值 | 约束 |
| --- | --- | --- |
| 墨色轮廓 | #242321 | 少量用于断面和关键轮廓，避免每个污点都描黑 |
| 炭灰暗部 | #393733 | 墙缝、湿路、设备内腔 |
| 柏油中间色 | #4B4842 | 路面低对比背景 |
| 混凝土 | #777268 | 大面积结构主体 |
| 干燥亮面 | #A49B88 | 墙顶与盐蚀，避免接近提示文字亮度 |
| 尘土褐 | #75634E | 木、泥及积尘的主色 |
| 暗锈红 | #784D3D | 金属接缝与锈蚀下缘 |
| 锈色亮部 | #A27351 | 少量剥落边缘 |
| 灰蓝深水 | #394B50 | 可和普通路面区分 |
| 灰蓝水纹 | #687B7B | 稀疏水面亮纹，不铺满高光 |
| 暗苔绿 | #59604A | 局部潮湿生物痕迹 |
| 暖黄灯光 | #C3A26A | 局部导航与有人使用的设施 |
| 污白标签 | #C9C0AC | 少量关键物件结构，与地面纸屑区分 |

主画面以灰、褐与暗锈为主，海水保留灰蓝，赤潮保留可辨认的异常色。不要把全图罩成同一棕色，也不能用整体压暗营造废土而丢失敌人、门洞和物资轮廓。文字、中文招牌和功能符号由项目可控的文字/符号层处理，不依赖 AI 在贴图上生成可读中文。

### 3.3 光照与噪点

环境光统一来自屏幕左上，投影朝右下。主体可保留固有明暗和接触缝隙，长投影单独制作；分离层不得在主体上再留一份同样的黑影。室内灯光只提供局部暖色和亮度变化，不引入新的可见性、隐蔽或照明战斗数值。

细节按用途分布：盐渍沿墙脚、金属锈蚀沿焊缝与积水处、木板磨损沿踏步路径。以成簇像素塑形，避免全图随机噪点、摄影纹理、柔焦、景深和抗锯齿光晕。干净/破损/潮湿变体来自稳定坐标或独立外观种子，不能调用行动 RNG 改变掉落或战斗结果。

## 4. 材质与区域素材清单

### 4.1 材质语言

| 材质 | 方向与明暗 | 磨损与变体 | 拼接/识别要求 |
| --- | --- | --- | --- |
| 柏油 | 大面积低对比、稀疏颗粒 | 裂缝、补丁、湿斑 | 连续路面无棋盘明暗；裂缝有独立贴花 |
| 混凝土 | 宽色块、板缝与顶缘亮线 | 缺角、盐蚀、水线 | 区分地面和立面；墙脚与地面接触明确 |
| 瓷砖 | 规则接缝、单侧微亮边 | 缺砖、污水、褪色 | 32 格边缘接缝连续，不能每格重复抢眼污点 |
| 木板 | 沿板长的直线纹理 | 断边、潮湿、钉头 | 码头方向遵循现有通路；断板不伪装新增坑洞 |
| 锈铁 | 硬边与少量金属高光 | 焊缝、下缘锈、掉漆 | 可交互箱盖与装饰铁皮区分 |
| 波纹铁皮 | 同尺度平行波纹、交替窄明暗 | 折角、钉孔、锈条 | 墙段之间波距一致，屋面与墙面不混用方向 |
| 玻璃 | 深色内部、窄亮边与少量反射 | 裂纹、蒙尘 | 开口位置和当前窗户规则一致，不画成可走空门 |
| 泥滩 | 横向潮线、短裂纹、软色块 | 干裂/湿润两态 | 与深水、永久干路清楚区分，岸边有过渡块 |
| 海水 | 稀疏横向波纹、灰蓝层次 | 平静/扰动、赤潮边缘 | 基础块与岸线边角分离；不以装饰水纹扩大洪水范围 |

可重复地面必须检查 3×3 铺贴。岸线、道路和墙角分别准备中心、边缘、内角与外角；素材不足时明确缺项，不能将“提示词写了无缝”当作拼接已通过。动画水面先用静态合格基底验证，再补低幅帧变化；不把角色、提示或地形边界一起画进水面帧。

### 4.2 区域配置

P0 为视角可用和正确读图必需；P1 为区域识别；P2 为氛围扩充。先完成共用 P0，再按城中村 → 水产市场 → 观测站 → 旧渔港 → 泵房验证；顺序是素材制作顺序，不改变地图路线。

| 区域 | P0 必要模块 | P1 特色道具 | 可复用变体与 P2 |
| --- | --- | --- | --- |
| 共用道路与岸线 | 柏油、混凝土、泥滩、水面、岸线边角、墙/门/窗/屋顶、人物八方向 | 箱子、告示、现有物资与撤离识别 | 干湿、褪色、破损；纸屑与小片盐渍 |
| 城中村巷道 | 居民楼灰墙、波纹雨棚、瓷砖室内、原门洞和楼梯识别 | 空调外机、卷帘、修理台、管线 | 灰墙共用；差异放在窗框、门牌底板和墙脚水线 |
| 水产市场 | 摊位基座、冷库板墙、防滑地面、排水沟 | 鱼筐、冰鲜柜、磅秤、遮阳棚 | 同一筐体的空/满视觉版本只绑定真实状态；不得凭贴图创造物资 |
| 潮汐观测站 | 工业混凝土、实验室地面、设备墙、既有门窗 | 仪表柜、采样台、观测设备、封存柜 | 灰蓝设备漆、锈铁底座与暖黄状态点；状态灯无新规则 |
| 旧渔港 | 码头木板、堤岸、系船柱、船务所模块 | 岸外船体、绳盘、渔网、装卸道具 | 共享木板/铁皮；船体不变成新可走平台 |
| 海堤泵房 | 混凝土围护、湿地面、设备基座、原出入口 | 泵机、阀门、管道、配电柜 | 复用观测站金属体系，以粗管径和锈水线区分 |

已有室内/楼层使用所属建筑的材质体系；层间入口、门窗状态和区域身份沿用当前数据。新绘制的高箱或设备必须映射已有等价实体；若只是贴花，不得画成明显堵路的高实体，产生“看起来堵住但可以穿过”的误导。

## 5. GPT Image 拼板生产规范

### 5.1 允许的用途与默认策略

**后续获准的素材制作任务可以调用 GPT Image，优先一张图生成多组同类素材。** 本次文档授权不意味着现在开始批量绘图。优先使用当前环境提供的内置绘图能力，不因拼板自动改为收费 API 批处理；模型、尺寸和透明能力以执行时实际工具及 [OpenAI 官方图像文档](https://developers.openai.com/api/docs/guides/tools-image-generation)为准，不编造模型名称、固定价格或额度上限。

默认约 1024×1024 源图。该图是候选素材板，不是能直接装载的运行图集：生成后仍需检查布局、切分、规范尺寸、锚点、色板与 Alpha。单图减少重复调用的机会，但总成本受尺寸、质量、失败重试和实际计费方式影响，不承诺按格数线性省额度。

| 类别 | 默认排列 | 槽位数 | 同板内容 | 源图槽位参考 |
| --- | --- | --- | --- | --- |
| 地面 | 4×4 | 16 | 同一材质体系的基底、磨损和潮湿变体 | 1024 图上每槽约 256×256 |
| 小型道具 | 4×4 | 16 | 同尺度、同材质类别的箱、桶、筐等 | 每槽约 256×256 |
| 墙面与门窗 | 3×3 | 9 | 同一建筑体系的可拼接模块 | 每槽约 341×341，不能假设整数等分准确 |
| 大型道具 | 2×2 | 4 | 泵机、摊位、船体等 | 每槽约 512×512；细长物不足时单独改画幅 |

3×3 的概念分区可用源图边界 0、341、683、1024 规划，但裁切必须依据实际像素复核；误差不能沿用到最终图集。道具每侧保留约槽位宽高 1/16 的空白，主体与独立阴影都不能跨格。地面方块之间也保留可识别间隔，切分后只保留方块本体，不把间隔带入可平铺图块。

### 5.2 槽位清单与素材登记

每次生成前以文字表固定行列，从左到右、从上到下列明内容；编号仅存在清单，不绘入图片。一张板不混合地面、直立人物、大型建筑与库存图标。角色朝向板单独组织：八方向按 4×2 或两行槽位排列；同一角色的方向/动画不可与随机道具共板。

登记表至少包含以下信息，本文只规定文档字段，不增加运行时类型或 API：

| 信息 | 要求 |
| --- | --- |
| 稳定素材标识、版本、用途 | 示例 coast-prop-fish-crate-v1；不是新的存档 ID |
| 原图及提示词 | 原始输出单独保留，标明参考图用途，不覆盖原图 |
| 生成日期与工具/模型 | 记录实际可知信息；未暴露模型时填“工具未提供”，不能猜测 |
| 槽位内容及实际裁切矩形 | 源图左上为原点，记录 x/y/宽/高及实测源图尺寸 |
| 成品尺寸与锚点 | 区分画布边界坐标、可见包围盒和地面接触点 |
| 图层及占地映射 | 主体/阴影/上片、朝向、对应现有实体或装饰；不得从图片推断碰撞 |
| 材质与变体 | 色板、干湿/破损含义及可复用范围 |
| 整理与验收记录 | Alpha、接缝、像素修整、淘汰原因；合格文件的哈希用于追溯 |

生产原图可建议归档在未来的 assets/coast/sources，整理后的运行资源位于 assets/coast；本次不创建这些素材目录。只内联实际使用的运行图集，不把全部候选源图和预览拼板塞入离线 HTML。

### 5.3 可直接使用的提示词

下列模板以共用灰褐废土色板、左上环境光为固定约束。需要变更题材时只替换槽位清单，保留视角、尺度与裁切要求；不要求模型在图上打印参数。

**地面材质板：混凝土，4×4**

> 绘制一张约 1024×1024 的游戏像素素材板，4 行×4 列，16 个独立、不透明的正方形混凝土地面候选块，各格之间留清楚的空隙，背景不作为素材。视角为正俯视方格地面，没有透视、菱形网格或地平线。目标成品每块 32×32 逻辑像素，请以清晰的粗像素簇设计，而不是摄影纹理或细密噪点。低饱和灰褐废土，混凝土主色 #777268，暗部 #393733，少量亮面 #A49B88，左上环境光。第一行依次为四种低对比干燥基底；第二行为细裂缝、缺角修补、磨损、积尘；第三行为浅湿斑、深湿斑、盐渍、退水痕；第四行为前三类中细节最少的四种过渡变体。每个方块自身四边适合重复铺贴，重点细节不要卡在边缘。不要人物、建筑、道具、文字、编号、格线或装饰边框。各方块保持相同尺度和亮度体系。

**小型道具板：水产市场，4×4**

> 绘制一张约 1024×1024 的透明 PNG 像素素材板，4 行×4 列，各格只放一个独立物件；真实透明背景，不画白底、棋盘格或街景。俯视方格地图配可见正面立面的游戏视角，非等距菱形，左上环境光、灰褐废土、暗锈红与少量灰蓝。统一尺度，目标成品以 32×32 或 32×64 画布整理，每格四周至少留约 1/16 空白。槽位从左到右、从上到下：旧木鱼箱、褪色塑料鱼筐、带盖泡沫保温箱、矮铁桶；手提水桶、空绳盘、折叠渔网、旧磅秤；单层空货架、低矮工作凳、排水格栅、壁挂管线；小配电箱、独立阀门、折起的布篷、旧工具箱。各物件脚底和接地面清楚，不互相重叠，不跨格。主体保留固有明暗，不烘焙长投影，不生成物资图标、可读字、编号、标志或光晕；保持硬像素轮廓，避免平滑渐变。

**建筑模块板：居民楼，3×3**

> 绘制一张约 1024×1024 的透明 PNG 建筑模块素材板，3 行×3 列。用于正交俯视地面＋向屏幕上方延伸的可见墙面；地面方向横平竖直，没有消失点或菱形等距投影。统一灰褐混凝土、左上光，标准成品墙段画布 32×64，脚底基线一致，模块之间留白。第一行：完整灰墙、带盐渍的灰墙、带窄窗的灰墙；第二行：关闭木门、对应的开启木门和完整门框、同宽空门洞框；第三行：墙体左端收口、右端收口、单段波纹铁皮雨棚。相邻墙体的墙顶高度、砖缝与接地线一致，门窗不得向旁格延伸。真实透明背景，不生成房屋全景、屋内物品、地板背景、编号、文字、品牌、投影或阴影底板。窗户用暗色玻璃和少量硬边反射，所有边缘为清晰像素簇。

门模块的“开启”只描述制作外观；实际是否开启由现有门状态决定。墙角、屋顶和双格门另建同体系拼板，不把上述 9 格误写成覆盖整套建筑。

**局部返修模板**

> 编辑所附原始素材板，仅修正清单中的第【行】行第【列】列【物件名称】：【具体问题，例如多余底板、方向错误、主体被裁切】。保持其他格位的内容、布局、尺度、色板、光向和透明背景；目标格物件仍须完整落在原槽位内，不新增文字或边框。不要重新设计整张图。输出后将与原图逐格对照，只采用通过检查的修正格。

模型不保证其他格位逐像素不变；实际返修只采用经过核对的目标裁片，其他合格素材继续使用原版。若一次返修仍串图或结构错误，拆成较小板或单格返修并记录原因，不无限整板重生。

### 5.4 固定工作流与淘汰条件

1. **清单与槽位规划：** 先查已有素材，确定可复用模块、缺项、目标尺寸和每格内容。
2. **小批试样：** 同一张试样板验证尺度、光照和色板，先包含一个地面/墙体体系或一组同类道具，不混排所有类别。
3. **风格确认：** 在 32 像素地块与 32×48 角色比例下比较原尺寸、灰度和放大图；未经确认的试样不扩成全地图素材。
4. **分类拼板：** 使用已确认样例作为风格参考，分开地面、道具、建筑与人物，保留完整提示词和槽位表。
5. **切分与像素整理：** 核实实际尺寸与 Alpha，逐格裁切，去除空白背景/假棋盘，统一画布、脚底和色板；先以最近邻缩放作底稿，再逐像素修形，不以双线性缩小冒充像素成品。
6. **验收与返修：** 平铺块做 3×3 拼接，道具做原尺寸与脚底对齐检查；只返修不合格项。合格项原始版本保持不变。
7. **运行图集准备：** 整理后的图块重排入真正图集，帧外保留 2 像素隔离；地面边缘可外扩重复边色、道具保持透明，读取帧矩形不含隔离区。整图集大小按实际打包测量，不以生成源图大小硬定。

淘汰：错误视角、尺度漂移、跨格串图、截断主体、假透明、错误接缝、抗锯齿白边、与碰撞含义矛盾的轮廓、阴影重复、过密噪点、方向不一致。生成成功只代表得到候选图，不代表上述检查通过。
