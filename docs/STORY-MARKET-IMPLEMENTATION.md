## 4. 必须保住的行为与接线决策

- 主档仍使用 `escape-bincov.session.v2`；剧情、profile、RPG、活动世界、容器余量和结算放在同一正式记录，不新增第二个剧情存储键。版本5只是拟议方案，实施前再次核对版本占用与2MiB上限，迁移备份不递归膨胀。
- 见闻是已提交的玩家知识，行动失败后可以回顾；实体物资仍按背包/安全箱的原失败规则处理。报告、选择、开柜、取物、维修交付逐项注入写入失败，不能先播成功再保存，也不能通过退出对白绕过故障。
- 固定补给按出击扣账前的仓库/背包/安全箱合计缺额计算，一局生成一次。背包满不发剧情凭证，不代为交任务；完成repair后停止补给，不重发现金。基础投放预算与非中性RPG幸运的现有增减产分别记账，不以最终物品件数替代来源记录，也不抹掉已接受的幸运规则。
- 保留离层一次子弹结算后冻结源层的规则，全局行动时间、潮汐与追击按既有设计继续。局内短交流、阅读及容器沿用现有时间语义；危急提示优先且所有关键声音有文字对应。
- 剧情知识只从真实交互获得；repair=true不能补造 `breaker-down`/`heard-call`/报告/选择。`defer`可改`told`，关闭不选择，不以措辞或隐藏分数处罚人物。
- 院子Runtime、经典界面、Phaser行动和Pixi样板调用同一正式叙事服务。市场P0先使用现有程序图形与合成音，装饰表现不消耗战斗RNG，沿已接受规范；不把代码细节写进玩家对白，不强制配音或生成新PNG。
- 叙事日数不映射现实等待、十分钟行动或累计出击次数。普通撤离只是回水产站，本片段不显示可完成的县外逃离或工厂任务。
