## 3. 技术方案与必须保持的不变量

以下为建议实施结构，名称可随代码审阅调整；不是已经存在的 API，也不要求整仓重构。

### 3.1 状态与模块边界

| 层次 | 持有内容 | 建议落点 |
| --- | --- | --- |
| 永久档案 | 现金/库存/任务、身体状态、永久属性/余数、声望、幸运、设施与有限队列、时间游标 | domain.ts 与拟新增 rpg.ts、base.ts 的纯类型/规则 |
| 整局共享状态 | runId、世界/地图修订、当前地图、唯一角色、全局行动时间/潮汐、成长账本、RNG/实体分配器 | checkpoint.ts 与拟新增 raid-state.ts |
| 每图状态 | 门、普通敌人、物资/容器/尸体、当前层弹丸、本地冷却/噪声及必要时间 | world.ts 地图定义与多图快照 |
| 跨层事件 | 唯一敌人、来源/目标入口、路径和进度、预计到达、排队状态 | 拟新增 traversal.ts；不依赖场景对象 |
| 规则计算 | 碰撞、弹道、伤害、成长、生产、恢复均返回候选或明确事件 | 现有纯逻辑模块及必要的小模块 |
| 提交与表现 | SaveSession 构造/验证/写入候选；成功后场景切换、声音、提示 | session.ts / recovery-store.ts；game.ts / ui.ts 只适配表现 |

角色只能有一份权威身体状态；档案与快照若需兼容投影，必须在一个提交点生成并交叉校验，不能分别修改。静态地图不必逐次保存整张格子，但必须用不可变世界/布局修订定位，并在升级后仍可恢复旧布局。

### 3.2 三类时间

| 时间域 | 推进内容 | 停止条件 |
| --- | --- | --- |
| 全局有效行动时间 | 600 秒时限、潮汐、追击、角色生存/限时效果、合格训练 | 显式暂停、后台、故障、终局；离线不补战斗 |
| 当前地图本地时间 | 普通敌人、巡逻、攻击、弹丸和本地噪声 | 离层弹丸一次结算后冻结；返回不补离开时长 |
| 现实时间 | 基地期间恢复/治疗/限时效果；任何位置的已启动生产 | 恢复到上限、有限队列完成或待领取区阻塞；行动暂停不暂停生产 |

现实时间推进按位置改变、buff 到期、上限改变、设施升级、批次完成/阻塞分段；时钟回拨差值取 0、游标不后退。采用事件边界计算，不逐秒回放数天离线。

### 3.3 换层事务原型

1. 捕获同一时刻的权威状态；先处理应到的全局事件和终局，死亡/超时优先，拒绝故障、冲突或面板透传。
2. 验证入口配对、身体距离/通路、目标地图及落点：指定点优先，否则 64 像素圆内格中心按距离、行、列选取。无落点不结算来源弹丸。
3. 记录换层瞬间实际目击且有合法路径的追击候选。在内存候选中移动玩家，并按稳定弹丸次序结算来源层剩余合法轨迹；不推进普通 AI/行动时间。
4. 共用战斗内核处理伤害、实际损血成长、击杀、尸体、幸运和 RNG；被击杀的追击候选取消。存活追击者登记唯一事件，来源层清除在途弹丸并冻结。
5. 校验地图/角色/门/实体/事件/库存/随机状态，连同同一事务涉及的基地生产结果一次写入；失败恢复完整前态并保留可重试候选，拒绝重抽随机结果。
6. 成功后才切画面、更新 HUD、关闭旧搜刮/拖放并抑制旧持续输入。事务回滚与真正读档/换层分开，保留现有“无效操作不清空按键”的桌面语义。

新世界采用可复现的弹丸处理次序和碰撞并列规则，M0 先定稿并记录；旧海岸不能悄悄改用新的随机调用序列。新弹道需按剩余有限线段找合法首碰撞，不能用无限直线隔墙寻找目标。

### 3.4 持久化与唯一性

- 每个敌人仅属于某张地图或某个追击事件。来源可视化是该事件的投影，不是第二个实体；一个敌人最多一段未完成追击。
- 每份物资只能位于一端库存、地面、容器或生产区；世界 ID、物品 UID、批次 ID、掉落来源和成长事件均可追踪。
- 事件重试、尸体生成、任务/设施奖励、训练差额和批次领取不得重复入账；重放使用同一候选/种子状态及稳定分配器。
- session/profile/raid/活动与已结算备份版本一起定稿。保留主档键、旧原始字节、严格导入和写入所有权；未知字段/版本不能被旧端忽略后覆盖。
- 建立旧 coast-v1、coast-v2、新建筑世界、新商场世界的恢复分流；旧活动局完成前不补地图、敌人、物资，不重发历史训练或任务奖励。
- 导入同一旧备份本质上可能恢复历史进度。需定义已处理时间/批次凭据在覆盖导入中的合并保护规则，防止生产结果与恢复的旧队列同时存在；不能承诺离线客户端抵御任意删档、换设备或手改 JSON。
- pendingSettlement 必须包含新成长、身体状态与生产相关候选/备份信息；提交失败时不显示永久收益，也不开始基地恢复。
