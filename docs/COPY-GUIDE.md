# 玩家文案约定

适用于游戏画面、按钮、键盘提示、悬浮提示、读屏标签、物品与任务说明，以及 README 和便携包中的游玩说明。玩家可见名称与代码 ID 分开维护；改名称不能顺带改存档键、物品 ID 或规则。

## 怎么写

- 按钮写动作，提示写结果。优先说明发生了什么、玩家下一步能做什么，省去「进度保护」「消灭威胁」等泛化表达。
- 同一功能的可见标签、读屏标签和游玩说明保持一致。短提示可用简称，但必须能从详情找到全名。
- 规则先于气氛。失败提示明确写背包物资和主武器丢失，安全箱内的物品和水手匕首保留；不能概括为「所有随身物资遗失」。
- 医疗物品直接写实际效果。Q 只调用背包中的绷带或急救包，不能暗示自动使用除藻药剂。
- 时间写清起点：预警在出击 4 分 30 秒后，潮位在出击 5 分钟后变化；HUD 主计时器显示剩余时间。
- 环境留言和电台对话可以有怪谈气氛，但使用可想象的物件、动作和人的口吻，避免每段都用灯、潮声、盐雾收尾。
- 保存失败时不要写成成功，也不要把下载请求当作文件已落盘。提醒玩家确认备份下载完成；多个窗口的进度不会合并。
- 玩法提示不塞实现术语。版本、调试种子等确有用途的内容保持简短；编程、打包和验收方法放在开发文档。

历史验收报告及截图保留当时的文案，不为统一术语回写历史。新文案应检查桌面两种分辨率及手机主菜单，尤其是指南、长物品说明、结算和存档错误面板。
