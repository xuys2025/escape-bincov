# 城中村样板声音接通（Opus）

2026-10-08（UTC+8）。原分支 `docs/coast-2-5d-art-design`，接 `717856d`（第五轮试玩整改）。

## 问题

接手时样板里**完全没有音效调用**：开枪、近战、受击、脚步、拾取、换弹、无线电和结算都不发声，只有点击菜单时起的海浪环境声。

切出窗口后，原有的全局失焦处理会调用 `audio.stop()` 挂起音频，但样板没有任何地方再把它启动，所以切回后一直无声。

[整改前的实测](evidence/audio-old-717856d.json)：14 项里只有「环境声」通过，[波形](evidence/audio-waveforms-old-717856d.png)。

## 做法

接通游戏**已有的** `SynthAudio`（全合成，不读取任何文件，离线可用）。新增 `src/coast-view/sound.ts`，按原 Phaser RaidScene 的用法驱动它：只读取 Runtime 发布的事件和 HUD 状态变化，不改动模拟。

| 声音 | 触发 |
| --- | --- |
| 开枪 | `shot` 事件：玩家按武器类型播放（手枪、霰弹枪、卡宾枪），敌人一律用 `enemy` 音色 |
| 近战 | 玩家的 `melee` 事件，匕首音色。与原版一致，敌人挥击不单独发声，打中时由受击发声 |
| 受击 | `hurt` 事件，且伤害 ≥ 1。流血和污染每帧都会发一次不到 1 点的小额 `hurt`，这些不发声（见下文） |
| 脚步 | 玩家移动时按原节奏：步行 0.42 秒一步，疾跑 0.25 秒一步，第一步立即响 |
| 拾取 | `looted` 事件（地面拾取、从箱子或尸体取物），Q 治疗（治疗次数减少时），背包里使用补给 |
| 换弹、开门 | 换弹开始和结束各一声 `click`；开门 `click` |
| 无线电 | 显示无线电消息时（阅读纸条不算） |
| 结算 | 结算写入成功时：撤离播放上行和弦，失败或放弃播放死亡音。原版的提示音写在 `ui.ts retrySettlement()` 里，样板走 Runtime 自己的结算服务，所以这里补上 |

- **跟随阶段挂起与恢复：** 音频跟随发布出来的阶段。只要阶段是 `paused` 就挂起（Esc、失焦、切走标签页、卡顿、图形上下文丢失都会进入这个状态），一旦恢复运行就重新启动。所以切出再切回后，点「继续」声音就会回来。
- **音量：** 样板的暂停面板补上了与原版暂停菜单相同的「游戏音量」滑块，写入同一个存档设置；基地「水产站」页的滑块也照常生效。
- **附带修复两处每帧刷屏：** 流血时 Runtime 每帧都发一次小额受伤。如果直接映射成受击音，会出现连续不断的击打噪声（[未过滤时的波形](evidence/audio-waveforms-bleed-spam-unfiltered.png)「enemy attacks」一行后半段可见）。同一批事件原本还会每帧触发玩家白闪、抖动和血雾，也一并只对真正的打击生效。

## 实测方法

`scripts/coast-audio-test.mjs` 不靠调用次数判断。它在 AudioContext 的输出端（限幅器到 destination 之间）接一个 ScriptProcessor，逐块测量**实际渲染出来的**波形，记录峰值、整体 RMS 和高频强调带。同时记录每个 Runtime 事件到达的时间。一个音效只有在对应事件之后 -60～+350 ms 内出现真实的起音，才算响了。

- 浏览器**不加** `--autoplay-policy=no-user-gesture-required`，因此和真实玩家一样受「需要用户手势」的限制。
- 撤离和弦的四个音（330、440、550、660 Hz）分别用 Goertzel 检测：每个音都要高于结算前该频点水平的 3 倍，四个音平均高于 4 倍。330 Hz 与海浪环境声在同一频段，所以单独放宽。
- 切换标签页：先真的打开另一个标签页并切到前台；但 headless Chrome 下原页面仍然是可见且有焦点（已记录），所以改为派发游戏实际监听的 `blur` 和 `visibilitychange` 事件，同时让 `document.hidden` 报告为 true。**真实的窗口切换没有在本机自动化环境里验证**，需要真人试玩确认。

| 检查 | 实测结果 |
| --- | --- |

## 交给 GPT 侧：音频服务缺陷

`SynthAudio.start()` 恢复 AudioContext 是异步的，而提示音方法在状态还不是 running 时会**静默丢弃**。所以挂起后刚调用 `start()` 就请求的提示音会丢。

- 实测原游戏（main `841e8bb` 也一样）：从暂停菜单放弃行动后，死亡提示音没有响。开枪峰值 0.24，放弃后的输出只有 0.05，也就是环境声水平。
- 样板目前在前端绕开：先 `start()`，150 ms 后再播结算音。这只是**变通**，不改 `src/audio.ts`。

服务层修复建议由 Astra 负责：让 `start()` 返回恢复完成的 Promise，或者在恢复期间把提示音排队。Sol 负责回归。修好后，Opus 撤掉样板里的延迟。复现记录在仓库外的工作标准：`工作标准/缺陷登记/音频服务丢失恢复期提示音-20261008/`。
