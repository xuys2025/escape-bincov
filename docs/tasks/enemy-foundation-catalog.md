# EN-01：敌人内容目录与旧映射边界

本交付承接 [Issue #78](https://github.com/xuys2025/escape-bincov/issues/78)，依据 [ENEMY-DESIGN](../ENEMY-DESIGN.md) 建立十八张卡的稳定程序身份。目录位于 [enemy-catalog-data.ts](../../scripts/enemy-catalog-data.ts)，身份、条件敌对与兼容风险由 [enemy-catalog.test.ts](../../tests/enemy-catalog.test.ts) 检查。前十一条为 `street-prototype`，身体/行走/尸体素材为 `body-and-corpse`；其余七条整项交付仍为 `design-only`，十八类素材均为 `body-and-corpse`，部分共享机制不等于完整原型。动画需求列表仍是目标规格，不能把 468 张帧图当作搬运、查账等全部情境动画已完成。

`ENEMY_CATALOG` 按设计编号排列，每条包含稳定 ID、阵营、默认立场、接敌与脱离条件、平时/警觉/交战/搜索行为、武器类别和素材需求。`ENEMY_FACTIONS` 给出五类中文名称。表与嵌套对象均冻结。用 `pnpm enemy:catalog` 输出对照表，`pnpm enemy:catalog --json --id=raider-melee` 查看单卡。目录位于制作工具中，不进入游戏包或游戏字体扫描；实际新规则消费 [enemy-archetypes.ts](../../src/enemy-archetypes.ts)，旧类消费 [enemy-profile.ts](../../src/enemy-profile.ts)，不将整张设计卡写入存档。

## 旧四类的保守资源与行为映射

`LEGACY_ENEMY_PROFILES` 与 `getLegacyEnemyProfile(id)` 只承接当前四个 ID 的身体/尸体资源类别、武器外观、攻击分支和尸体随机搜刮次数。访问器拒绝未知字符串、对象继承键和十八个设计 ID，不提供默认回退。此表不拥有 `ENEMIES` 数值，也不修改旧名称或存档 ID。

| 旧 ID | 身体/尸体类别 | 武器外观 | 攻击分支 | 尸体随机搜刮次数 |
| --- | --- | --- | --- | --- |
| `scav` | scav | club | melee | 1 |
| `salt` | salt | rifle | projectile | 1 |
| `creature` | creature | claw | melee | 1 |
| `elite` | elite | rifle | projectile | 3 |

旧 `salt` 名称“盐枭”不意味着它现在成为卡 04；旧 `elite` 名称“守潮人”不意味着它成为卡 10；旧 `creature` 也不能直接代表蟹、犬或喷吐兽之一。旧四类没有足够信息推断十八类的身体、阵营、条件敌对或 AI。既有活动行动与历史地图保持原 ID 和资源映射；未来新增敌人需要独立生成、战斗、素材和存档方案，不能通过目录查找静默改写旧档。

## 最初选址提案（历史依据）

下列选址已由[街区样板](enemy-street-encounter.md)落实，并完成 100 种子、潮位/入口、实际游玩及恢复验证；保留原提案以说明选择原因，不以其中“下一阶段”描述当前状态。

以下仅是下一阶段样板选址，不改变当前生成器。依据真实 [world.ts](../../src/world.ts) 的城中村道路、建筑与 `enemySpots`，以及 [building-world.ts](../../src/building-world.ts) 的 `BUILDING_WORLD.maps.coast`：建议近身掠夺者使用格 `(20,18)`，拾荒枪手使用 `(28,22)`，望风者使用 `(25,13)`。坐标均为零起点格坐标，像素中心为 `((x+0.5)*32,(y+0.5)*32)`；三点已存在于 `enemySpots`，当前街区图均为室外 `floor`，不在居民楼楼层入口两格内。2026-10-23 补强测试确认每点距 `WORLD.spawns` 中每个出生点均大于十格；这只证明点位间距，不替代完整路线、视线或警报范围验收。

近身掠夺者在海声修理铺东侧通道 `(20,18)` 围绕搬运残料活动；枪手在停业杂货铺南侧外缘 `(28,22)` 守局部货堆，可从宽街观察并绕行；望风者在船工宿舍南侧巷道 `(25,13)` 观察街口，不能躲在不可达屋顶。保留西侧 `(5..7)`、中部 `(33..35)` 与横向 `(23..25)` 的高地道路作为绕行候选，最终视线、可达性、出生隔离和高低潮路线仍须在实际遭遇实现时验证。

三种原型用于比较近身、守点和通报三种职责，不意味着三人从这些分散位置全图共享情报；未来通报只触及真实可联络的据点。首版若决定组成同一处三人遭遇，须结合可达范围重新收拢阵位并验证警报距离。正常住户、学校联络点、问诊和返站路线不被自动视为敌据点。检查哨兵留待有等待区、限制线与合法公共路线的专门设施样板；现有北线“检查口”撤离点名称不能直接证明条件敌对设施已具备。

## 旧世界观与主线人物的归属

[WORLD-REGIONS-STORY](../WORLD-REGIONS-STORY.md) 仍将盐枭列独立势力，将自由拾荒者与守潮人作为有正常生活、交易与分歧的人群；[MAIN-STORY](../MAIN-STORY.md) 继续是具名人物经历的来源。目录采用 ENEMY-DESIGN 的五类战斗内容组织，不把组织重分类当作剧情改稿授权。后续应由剧情/阵营实施任务统一设定索引，再定义具体事件与关系状态。

| 人物或群体 | 需要保留的故事事实 | 后续归属与目录边界 |
| --- | --- | --- |
| 宋姐及医院旧址住民 | 以旧病历换药，带普通拾荒者居住并为撤离争取作保 | NPC、住民与交易/任务事件；不以 `raider-melee` 等随机生成，争议侧楼暴力团伙须另标范围 |
| 林满仓、鲍经理 | 同称盐枭但动机不同：救人船主与隐瞒风险的掮客；有各自运输线与结局行为 | 具名剧情人物；不被 `raider-boss` 重复生成或统一见面敌对 |
| 顾阿婆与普通受盐患者 | 温和派庇护、病人休息与正常生活 | NPC/医疗和庇护空间；不进入盐蚀者随机目录 |
| 老蔡（蔡建平） | 岬角宿舍走廊角落听广播，保持其人物关系 | 独立剧情状态；外露盐晶不是 `salt-dazed` 生成依据 |
| 顾海生 | 激进立场与丧亲经历，主线保留非致命化解冲突 | 独立对话/事件与结局条件；不等同通用 `tide-ritualist` 或旧 `elite` |
| 钟队长 | 掌管名单与隔离通行，合作、岗位责任和撤离分歧并存 | 独立剧情权限与事件；不等同重复生成的 `blockade-sergeant` |
| 工厂自治队、医院与研究人员 | 维修、救治、递物与通行关系各自成立 | 不因携武器、身处回收点或受盐而纳入十八类 |

EN-01 不实现声望、永久敌对、剧情攻击、非致命结局、十二张新地图或十八类随机投放。封锁队的警告升级和解除、佣兵任务冲突、动物护食等虽已写入只读卡片，仍需后续 Runtime 与事件实现，不能据此宣称玩家已可交涉。
