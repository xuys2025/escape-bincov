## 分级原则

按改动难度、根因确定性和依赖分三级，一级最容易；这不是严重程度评级。真实存档损失、交易不守恒或主流程不可用一旦复现，应立即重新排优先级，不能因列在第三级而拖延。

| 级别 | 含义 | 本轮处理 |
| --- | --- | --- |
| 一级 | 原因及位置明确，小范围字段或文案修正，不改规则 | 仅下面两项进入当前 PR |
| 二级 | 需要逻辑与显示协同、事务边界检查或素材接入 | 待下一轮安排 |
| 三级 | 难复现、底层资源归因、依赖真设备，或需要另定产品范围 | 单独调查/决策，不拖入一级 |

## 一级：本 PR 的两项交付

### T1-01：水产站计数文案（OPUS-STATION-COPY-01）

实际依据：[Runtime](../src/hideout-runtime/runtime.ts) 的 `snapshot().day` 是 `profile.stats.runs + 1`，[接口注释](../src/hideout-runtime/contract.ts) 已说明它不是日夜时间。[院子 HUD](../src/station-view/ui.ts) 和[电台面板](../src/station-view/panels.ts) 却显示“第 N 天”，[旧页签](../src/ui.ts) 还固定显示“第 17 天”。

- 目标：上述三个当前界面统一表达真实统计，例如“累计出击 N 次”，使用已有 `profile.stats.runs`；最终措辞遵守[文案约定](COPY-GUIDE.md)。不引入日历、不改出击计数、不重写历史报告或故事中的日期。
- 兼容：保留现有 `day` 字段及其注释，不为文案清理做破坏性接口重命名；日夜系统仍在第三级。
- 验收：新档为 0；累计出击为 7 的旧档三个入口一致；成功出击后增加一次，出击提交失败不增加，刷新与院子/页签切换不改变计数。1280×720、1920×1080 和手机窄屏可读，无缺字。
- 工作归属：逻辑侧确认统计语义；Opus 完成当前方案内的可见文案与接线；Sol 做集中复验。此文档不限制前端布局、技术选型或表现手法。

### T1-02：已佩戴护符快照（ASTRA-STATION-API-01）

实际依据：[HideoutSnapshot](../src/hideout-runtime/contract.ts) 没有护符字段；[院子 route](../src/station-view/route.ts) 用 `app.expansion?.charm?.id` 经 `StationHooks.charm()` 传给 UI。现状不等于护符无法使用，问题是展示数据绕开正式快照。

- 目标：在快照增加只读、可为空的已佩戴护符信息，由已提交的真实会话生成；院子整备通过同一快照显示护符，并删除这条专用共享状态回调。具体字段命名由实现者沿用项目约定。
- 范围：仅快照和接线；沿用现有 `equipCharm` / `unequipCharm` 事务、效果、负重及库存归属，不迁移存档，不创建第二份装备状态。
- 验收：未佩戴为空；佩戴/取下后快照、院子与旧页签一致；外部旧页签提交后刷新快照可见；修改返回数据不能修改会话；写入失败保持旧护符与原库存，重试不复制物品；刷新恢复一致。
- 工作归属：Astra/逻辑侧先补字段和事务边界测试，Opus 接快照，Sol 一次集中复验。未在本次准备中自动向其他聊天派工。
