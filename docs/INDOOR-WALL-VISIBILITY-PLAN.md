# 室内墙体与视野修改方案

> 状态：第一阶段（居民楼一楼、二楼、地下）已在 `feat/indoor-wall-visibility` 实施，商场楼层是第二阶段，见[§6](#6-实施进度)；合并与上线以该 PR 和 main 的 CI 为准。
> 设计核验基线 main `b5bd63b7896b3b0697d4ba38d02d000e78903047`（2026-10-28）。规则只在本页维护。

## 1. 目标与核验依据

覆盖居民楼、商场等所有室内场景。维护者已确认：保留完整墙体基础格，室内横墙按连续墙段整体切换。以居民楼二楼公共走廊的用户截图作为首要验收场景，五个标注对应下表。

当前实现的源码事实：

- [scene.ts 的 buildGeneric / updateFades / applyFade](../src/coast-view/scene.ts) 对居民楼等通用建筑的当前占用楼层统一进行网格淡出；墙和门的 `keepBottom` 为 6 像素。
- [mall-scene.ts 的 buildMall](../src/coast-view/mall-scene.ts) 保留商场墙体底部 32 像素，但仍接入同一淡出流程。
- [textures.ts 的 FADE_LEVELS / faded](../src/coast-view/textures.ts) 使用 1、0.7、0.45、0.25、0 五级像素网格；场景的 `applyFade` 在最高等级直接隐藏整个精灵，因此不能只把墙体淡出等级调到最高来实现“保留基础格”。
- [structure-guide.ts](../src/coast-view/structure-guide.ts) 的建筑占用、商场房间与走廊剖切规则属于显示规则；`shownAt` 等房间揭示权限必须继续独立生效。

以上为静态源码核验，未运行浏览器验证。核验时的[固定版本源码](https://github.com/xuys2025/escape-bincov/tree/b5bd63b7896b3b0697d4ba38d02d000e78903047/src/coast-view)用于追溯，后续实施前须重新核对最新 main。

## 2. 五项显示规则

“上方／下方”指地图画面的北侧／南侧，以玩家脚底世界坐标判定，不随瞄准方向、角色朝向或镜头移动变化。规则应用于玩家所在建筑的当前楼层。

| 标注及原图位置 | 修改后的表现 |
| --- | --- |
| ① 外围竖墙（37.8%，49.8%） | 保持完整实化，不因玩家靠近或进入建筑而虚化。 |
| ② 顶端外墙（75.4%，23.1%） | 保持完整实化，包括墙面和墙顶。 |
| ③ 底部外墙（45.8%，70.9%） | 玩家处于建筑内部期间，始终只显示完整墙体基础格；超出占地范围、向上覆盖行动区域的部分完全透明，不随距离切换。 |
| ④ 室内竖墙（65.2%，50.7%） | 保持完整实化；门洞上沿、横梁及相邻墙体伸入门洞投影范围的部分裁去，保证门口视野。 |
| ⑤ 室内横墙（75.0%，37.9%） | 玩家位于墙段北侧时，整段只保留基础格，延伸部分完全透明；位于南侧时恢复完整墙面。 |

补充约定：

- **基础格**是墙实际占据的地面格，通常为 32×32 世界像素；厚墙保留全部实际占格。保留原材质和阻挡辨识，不画成可通行地板。
- 横墙按门洞、开口、转角及交叉节点分段。同一段同步切换，不出现跟随玩家左右移动的局部缺口。
- 横墙以占地带中心线判断南北，前后各设 4 世界像素缓冲。玩家脚底越过北侧缓冲边界时切为基础格，越过南侧缓冲边界时恢复完整；缓冲区及边界上保持上一状态，首次加载位于缓冲区内时优先基础格。
- 切换直接在“完整墙体／仅基础格”之间进行，不使用网格残影或半透明过渡。
- 门扇继续表达真实开关状态；需要裁切时保留占地范围内的门扇、门框或门槛提示。关闭的门清楚可辨，打开后通道无遮挡。
- 转角和交叉墙按横、纵墙面分别处理。门洞净空优先，不能因竖墙保持实化而重新盖住入口。

原图仅是需求定位依据，不是修改后截图。本次不生成概念图或实现截图。

## 3. 后续实现方式与兼容边界

### 墙段与显示状态

在视图层根据现有地图格、建筑边界、门洞和墙体连接关系生成墙段，区分外围北墙、外围南墙、竖墙、室内横墙和门洞构件。居民楼、商场使用同一判定原则，各自适配现有绘图方式。

墙体增加独立的“完整／仅基础格”显示状态，替代室内结构的统一淡出路径。该状态及墙段缓冲记忆由视图持有，首次载入或换层时按当前玩家位置初始化，不增加公共 Runtime 接口或存档字段。仍适用本方案的墙体不能再被旧的角色焦点淡出规则覆盖。

基础格使用正确占地位置的材质切面；不能简单截取原图最下方任意 32 行，就把它视为正确的墙体占地。遮挡部分连同附着的招牌、装饰、发光层同步裁切，避免墙消失后留下悬空图形。角色遮挡描边检测同步读取裁切后的实际可见区域。

### 保留的规则与适配范围

碰撞、射击阻挡、门交互、房间揭示及未揭示房间压暗保持原规则。透明墙不能泄露隐藏敌人、掉落、尸体、弹着或其他效果；显示裁切结果不得成为可见性授权或修改 `revealed`。

家具、屋顶、室外建筑观察和封闭实心结构继续使用原规则。商场新旧布局、正式素材和程序绘制后备均需适配，不因换用新素材才得到正确视野。保留离线能力，不新增运行时网络请求或依赖。

本方案与 [PR #130](https://github.com/xuys2025/escape-bincov/pull/130) 的边界：#130 承接商场四版家具、地面素材接入；本方案规定墙体与门洞的显示裁切，不接管其素材替换、修图和 M3 验收。后续实施须核对 #130 的最新状态和重叠调用点，保留其已接受成果。

## 6. 实施进度

### 第一阶段：居民楼（已实施，待合并）

- 规则在 [wall-display.ts](../src/coast-view/wall-display.ts)（`wallRule`、`rowModes`、`doorClearances` / `clearanceCuts`）。[scene.ts](../src/coast-view/scene.ts) 的 `updateWalls` 每帧把它应用到玩家所在建筑的墙、门和开口横梁，这些墙不再走 `updateFades` 的淡出；整面、只留基础格和门洞裁切的图由 [textures.ts](../src/coast-view/textures.ts) 的 `wallCut` 生成，角色遮挡描边读实际画出的图。
- 方案没有写死、实施时定下的细节：
  - 转角和丁字交叉格先归所在的外墙；其余有东、西相邻墙格的算横墙，按所在行切换。例：二楼 (7,3) 既是竖墙顶端也是横墙西端，随横墙切换。
  - 横墙只比较脚底和该行中心线的南北，所以同一行被门洞分开的几段结果总相同，整行一起切换。
  - 门洞净空：门所在格加上方一个墙高（48 世界像素）的范围内，画在门之后（门以南）的墙块像素清零；门本身和门以北的墙不裁，关着的门完整可见。
  - 基础格用墙块自己的墙顶（图的顶部 32 行）画在占地格上；横墙上的门画两侧门框，中间是关着的门扇或打开后的门槛。
  - 开口上方的横梁在所在建筑内一律不画。
  - 测试夹具瞬移会让画面重建，按“首次载入”处理（在缓冲区内从基础格开始）；“缓冲区内保持上一状态”只在真实走动时成立。
- 验证：单测 [wall-display.test.ts](../tests/wall-display.test.ts)；`test:issue26-spatial` 的 S03、S04 改为新规则断言，新增 S04c（真实走动穿过缓冲区、像素 alpha、门洞裁切，两尺寸截图）。截图在 [indoor-walls/screens](indoor-walls/screens/)。
