## 事务与兼容的具体边界

- 存档仍是 `escape-bincov.session.v2` 的单条 v4 记录，扩展 version 2。无新键、无院子坐标/镜头/面板持久化，未改 RNG、潮汐、行动计时或奖励规则。
- 普通旧档在首次进入据点时升级；原 profile（钱、物品、任务、统计、设置）保留，既有 v1 扩展身体/成长/设施保留。legacyBackup、migrationBackup、systemsBackup 沿原 RecoveryStore 留存。未知/损坏数据不覆盖；非所有者只读。
- 活动旧版检查点不强转，恢复行动不重抽、不重新 beginRun。没有检查点的历史旧行动仍走原中断失败规则。
- 完整 v1 扩展备份导入到据点时可原子升级；包含活动行动则保留原版本后回菜单恢复。**已经启用成长的档仍拒绝只含库存的旧备份或无扩展的 v3 会话覆盖**，不能为方便导入丢掉身体/设施。这是现有 v4 降级保护；先在兼容旧版入口恢复旧备份、再进入新版升级。没有新增“强制清空成长”操作。
- 库存/设施/购物失败不更新 profile、body、queue 或 durable rev。storage 元信息会变为失败；windowLeft 是实时派生倒计时。训练每帧输入先留在内存，五秒或其他成功事务一起提交；快照展示已保存值，允许前端作显示插值但不能自行发奖。
- 失败的自动保存候选只允许原票据重试。旧页签的 persist、购买、设施、出击不能越过此候选。冲突不强行重试；保留完整备份，刷新重新取所有权。强制关页且未保存/导出的输入仍可能丢失，沿用原限制。
- 实时恢复与有限生产队列使用现有 advanceRealTime。离线可完成已付费有限批次、在基地恢复身体；满成品位后无用途的时间不会存成未来生产额度。训练不累计离线/隐藏时间。
- `day=stats.runs+1` 只是电台日志序号，不是昼夜或现实日期。STATION-NEXT-01 保留下一轮。
