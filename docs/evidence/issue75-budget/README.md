## H-10：帧耗时与峰值

测量脚本不入库，方法写在 `h10-summary.json` 的 `method` 里。ticker 照常运行，去掉开头 1 秒；补血的那一帧要恢复检查点，不计入耗时。两种场景：

- **真实混战**：海岸地图上 23 个活着的敌人都挪到玩家周围 150～390 像素，AI 开启；玩家按住 M4A1 转圈扫射，血量低于 60% 时补满。
- **高密度**：AI 冻结，真实画面每帧再加上检查 k 的负载（一名近处、一名远处枪手开火，一发子弹打墙），玩家同样按住开火。

main 和本分支交替各跑两轮。“处理耗时”是宿主每帧回调（Runtime 推进、画面更新和声音调度）的耗时，不含 Pixi 的绘制；“帧间隔”是相邻两帧的间隔，包含一切。

结论：

- **真实混战没有触发预算**：粒子最高约 200、声道最高约 60，都没到软上限，两轮都没有丢任何东西。两边的帧耗时在轮间误差之内，预算没有带来额外开销。海岸的 23 个敌人多数是近战，敌人开枪不多（20 秒里约 110 发，玩家约 110 发）。
- **高密度时预算起作用**：main 的粒子长期在 750 上下，声道整段顶在 96，新的声音只能等旧的放完才有位置；本分支粒子稳定在软上限 220 附近，声道约 70，丢掉的全是装饰（每轮约 1.6 万个粒子、9 千个声道），核心为 0。处理耗时 p50 从约 7.0 ms 降到 5.9 ms。
- 两种场景帧间隔的中位数都是 16.7 ms（被 60 Hz 刷新卡住），这台机器上看不出掉帧差别。

作废的一轮：本分支真实混战第 1 轮第一次跑时，玩家开打约 2.5 秒就被打死（20 秒里只录到 146 帧），这轮作废、重跑；作废记录留在 `h10-summary.json` 的 `discarded` 里。
