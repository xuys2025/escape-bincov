受击帧约 90 ms，恢复帧约 60 ms。帧率在 12 帧/秒及以下时，命中那一帧按“至少画一次”的规则显示受击帧，下一帧恢复帧的时长已经过去，所以不出现。闪白、后退与 #97 相同（60 帧/秒 4 帧）。

裁图与实景的做法：种子 42，冻结 AI；在当前批次的副本里把四类敌人排在玩家东侧，其他角色移到画面外，送一次合成的 `blow` 命中；停住 ticker，按 1/60 秒调用 `present()`。实景在 +4 帧调用 `app.render()` 后截取整页。脚本是一次性的，没有提交。

1280×720 下，人形受击时头部下沉约 6 个屏幕像素，比闪白和后退含蓄。这次只验证了帧序列和观感截图，没有做真人试玩或真机测试。

## 和 #81 的合并

本分支与 #81 head `1b884f2` 试合并，结果如下：

- **文本冲突**：只有打包生成物 `docs/release-manifest.json` 冲突，重新打包即可解决。
- **语义问题与修复**：第一次试合并时，#81 在 `syncActor` 里已经声明了局部变量 `pose`（攻击动作的形变），和本分支的同名变量冲突，导致编译失败。计时字段因此改名为 `hurtT`、局部变量改名为 `hurtFrame`。
- **改名后**：合并结果 `tsc` 通过，单测 747/747。
- **原型敌人防护**：用合并后的构建实测，给一个拾荒者加上 #81 的 `archetype: 'raider-melee'` 再让它中弹。10 帧里身体一直是原型自己的帧（`raider-melee` 第 0 帧），没有误用 A 组的受击帧，也没有退回占位图。同一个拾荒者去掉原型后，受击 5 帧、恢复 3 帧。页面无报错。
