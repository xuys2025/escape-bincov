## 1. 来源、目标与固定选择

原文依据为 [c940128 第一章《站里还有灯》](https://github.com/xuys2025/escape-bincov/blob/c940128e1959acb175955a30bdf6c4a81976d719/docs/MAIN-STORY.md)：维修单、旧交易厅后配电间、父亲工具柜第二层、冷柜两下声、拉下的总闸、回站询问和恢复供电。原稿中玩家没有告诉小蔡喊声，本样板新增“告诉／暂不提”的可选分支，明确属于改编。

玩家的必需行动是取得或备齐原维修物资，回站交付；调查总闸与交流喊声是额外人物内容。成功供电后仍需按原规则支付 ¥600 扩建仓库，不把任务改成免费扩建。

本批不强制首次引导、不锁旧三任务的交付顺序；不阅读可选长对白也能完成 repair。声音线索同步字幕，不要求配音。游戏接入后才提供真实截图，下面拓扑是设计说明。

## 4. 固定维修补给

### 4.1 需求与生成

原需求 `scrap:3, wire:2, fuse:1`，原任务 ID `repair`、奖励 ¥420、扩建费用 ¥600。出击前从尚未扣出 loadout 的同一候选 profile 读取仓库、背包、安全箱，避免迁移到 loadout 后漏计或双计。对每种物品：

```text
deficit[id] = repair 已完成 ? 0 : max(0, needs[id] - stash/bag/safe 的合计数量)
```

只在新叙事世界的出击生成步骤使用缺额；初始化后不随本局出售、丢弃、拾取或开柜变化重新计算。原任务仍允许来自任意正常来源的物资交付。缺额计算不读取旧界面的显示缓存。

“60份”指原生成器的60条投放记录，不是箱子数或物品件数；堆叠与分组后用来源记录计数核对。先生成原58条普通投放加sample／ledger两条任务投放，然后在分箱前，按普通记录原序取前 n 条非浅滩记录作为预留槽（n 为缺额大于0的品种数），改为对应品种的缺额堆，集中到工具柜。sample／ledger不参与替换，其坐标与数量不变。缺额最大3／2／1，都不超物品堆叠上限。

工具柜占一个容器名额。普通箱上限为 `min(9, floor((20-n)/2))`，普通箱每箱仍归入2条普通记录；任务柜承接n条。这样总归箱记录不超过20，总容器不超过10，散落记录不少于40，总投放仍为60。n=0时工具柜为空摆件容器，普通箱最多9个；不再生成专用物资。新规则只用于新世界，不要求与旧版相同种子产出逐件一致。

原有物资表经确定补给替换后资源比例会变化，“预算相同”不表示经济平衡已验证。重取与售卖沿用普通物品规则，不新增不可交易字段；缺额存在时再出击可以重新取得，完成 repair 后专用补给停止。真人经济验收记录卖出、失去与重取循环的影响。

### 4.2 算例

| repair／已有数量（scrap,wire,fuse） | 工具柜专用内容 | 来源记录n／普通箱上限 | 应有结果 |
| --- | --- | --- | --- |
| 未完成／(0,0,0) | (3,2,1) | 3／8 | 专用3记录＋普通16箱内记录，至少41散落 |
| 未完成／(2,1,0) | (1,1,1) | 3／8 | 只补差额，不发整套 |
| 未完成／(3,0,1) | (0,2,0) | 1／9 | 只发2卷线圈 |
| 未完成／(3,2,1) | 空 | 0／9 | 可直接交付；工具柜仍可调查 |
| 已完成／任意 | 空 | 0／9 | 不补料、不补奖，剧情见闻仍可探索 |
| 失败后安全箱保留(1,0,1)，其他为0 | 下一局(2,2,0) | 2／9 | 保留物计入已有量 |

实际容器余量、UID 与 loadout 同快照提交。背包满时不给剧情凭证，也不悄悄替玩家交付：留在柜里，允许原整理、部分取出和安全箱转移；离开／刷新后余量如实恢复。普通行动失败损失柜外背包物品，已保存的见闻仍在，下一局按剩余库存重算。

| ch01-dlg-reported | breaker-reported=true，主动“总闸的事” | 小蔡：“你说总闸已经拉下，我记着。” | heard-call且未told：“还有件事。”→call；否则“先走了。”→退出 |
| ch01-dlg-told | call-choice=told，主动重问喊声 | 小蔡：“喊声我也记下了。没看见人，先别认定是谁。” | “好。”→退出；不重复改变状态或发奖 |
| ch01-dlg-exit | 任意话题关闭／返回 | 界面立即关闭，不新增台词、不作默认回答 | 清理交互输入；已提交的状态保留，未选择项不写入 |

当玩家先报告后才听声，或先听声后才检查，话题按实际知识组合开放。tell使用的“总闸已拉下”要求真实观察，不能因heard-call自动成立。报告可以在维修前、维修后或一次失败行动后进行，前提都是对应见闻已成功保存且玩家已回站。

### 5.4 输入、时间与回顾

局内文字、声音及容器不暂停；对白字幕不占用移动／瞄准输入。打开容器沿用当前停止玩家移动攻击、世界继续的规则。Esc、触控关闭、失焦、死亡、超时、存档冲突清理面板和未提交选择，回到原保护行为；不设置新的暂停豁免。

新“见闻”入口在局内和站内可用，复用原阅读面板的时间语义。每条回顾有标题、玩家确实取得的文字和来源区域。危险消息优先，剧情最多显示一条短句；被挤掉的短句不排长队延迟到不相干场景，已保存内容可立即回顾。叙事声音未实现真人语音时用短合成音与字幕表达，不让听觉成为唯一证据。
